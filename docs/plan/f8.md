## F8 — One visual language for pcom (#209)

Status: planned · Depends on: the owner's approval of the mockups and the font choice · Branch: `feat/f8-design`

The app looks like stock Bootstrap. Fonts vary from page to page, and every page invents its own controls: edit
is a link in the feed, an icon on a post and a button on a comment. One settings form reloads the page, another
shows a toast, a third shows an inline message. This wave replaces that with a small design system of our own:
tokens, a type scale and a few components. Every page uses it, and Bootstrap goes away.

The design comes first and is made in Claude Design:
[pcom redesign canvas](https://claude.ai/artifact/6rkD8VEnriQeyFyxkRRBtG) (private to the owner). It has
the foundations sheet, the current site for reference, and mockups of the feed, a single post with comments
(desktop and phone), settings and the editor. Every artboard has the same three Tweaks: palette, font pairing
and dark mode. **No task starts before the owner approves the canvas**; comments left on it are folded into the
canvas first, then into this file.

Decided on 2026-10-04:

- **Bootstrap is dropped**, CSS and icon font both. pcom uses only its CSS (no Bootstrap JavaScript;
  `data-bs-dismiss` on the toast is dead markup). That CSS is mostly utilities (`mt-*`, `d-flex`, `col-*`),
  `card`, `btn`, `form-control` and `alert`, and the redesign replaces all of them anyway.
- **User CSS hooks stay stable.** User CSS is loaded on the journal, single post, feed and explore pages,
  inside `.user-styles-applied`. Its contract is the `us-*` classes, and they keep their names and meanings:
  `us-user-home`, `us-user-header`, `us-profile-about`, `us-feed-post`, `us-feed-post-stats`,
  `us-feed-comment`, `us-feed-rss-item`, `us-post-date`, `us-load-more`, `us-single-post`, `us-post-header`,
  `us-post-body`, `us-public-link`, `us-comment-stats`, `us-comments-section`, `us-single-comment`,
  `us-comment-form`. The other classes (Bootstrap's and pcom's own) can change. Today the guide doesn't list the hooks; T7 documents them.
- **The project website (`website/`) is out of scope.** It has its own stylesheet and stays as it is.
- **Not Substack's colors.** Cream with an orange accent reads as a Substack copy, so the mascot's orange
  stays in the logo only. The palette is chosen from the canvas: Graphite, Ink or Moss.
- **Fonts are chosen from the mockups.** The canvas offers three pairings. Whichever wins is self-hosted
  through `@fontsource` packages, so the CSP stays as it is: fonts load from `default-src`, which is self and the static CDN.

### The design system in short

The canvas's Foundations artboard is the reference. The rules a task must keep:

- **Tokens** are CSS custom properties on `:root`, redefined for dark mode (the
  `prefers-color-scheme` media query, and `[data-bs-theme="dark"]`, which T6 renames to `[data-theme="dark"]`). Ground,
  surface, sunken, line, text, muted, accent (from the chosen palette; text and links pass 4.5:1), ok, err. Spacing
  is 4/8/12/16/24/32/48/64; radius is 8 for controls and 12 for boxes.
- **Type**: a reading face for posts and comments (18–19 px, line height 1.65, a 680 px column), a UI face for
  everything else (15 px; 14 px for metadata), and a mono face.
- **Content is not boxed.** Posts, comments and feed items sit on the ground, separated by space and
  hairlines. A box is only for a form that opens in place, such as the comment composer or a comment being
  edited.
- **Item actions are one row of quiet text links** under the item: muted, one size, one order (comments,
  reply, edit, share, delete). There are no icon-only actions and no buttons inside content. A link post shows
  its URL as one muted line under the byline. A public link is one muted line under the actions
  (copy, turn off).
- **Buttons come in one size.** Primary marks the one main action of a form; every other button is
  secondary; destructive ones are secondary in red and always confirm.
- **Every form saves in place** and reports next to its submit button (saving / saved / not saved). Field
  errors sit under the field. There are no page reloads after a form, and no toasts for form results. Toasts
  remain only for results of actions that have no form, and they get pcom's own markup.
- **Settings is one column** with a section list on the left that stacks on phones.

### Structure of the work

New SCSS lives in `cmd/web/client/scss/`. It is split so that page tasks own disjoint files:

- `_tokens.scss` holds the custom properties, light and dark, and the font faces.
- `_base.scss` holds the reset, element defaults and `.prose`.
- `_components.scss` holds the shared classes: `.btn`, `.field`, `.meta`, `.acts`, `.item`, `.box`,
  `.status`, `.nav`, `.toast`.
- One partial per area: `_posts.scss`, `_settings.scss`, `_editor.scss`, `_auth.scss`, `_controls.scss`.

Until T6, the new classes live alongside Bootstrap, so each page can move on its own and the tree keeps
working. T0 creates every file (the area partials empty) and imports them; after that, each task edits only
its own partial.

### T0

Owns `cmd/web/package.json` and `yarn.lock` (the `@fontsource` packages for the chosen fonts),
`cmd/web/client/scss/index.scss` (the imports) and the new `_tokens.scss`, `_base.scss`, `_components.scss`
and the empty area partials. The components follow the canvas's Foundations artboard. Dark mode reads the
same tokens; `_dark-mode.scss` loses every rule the tokens make redundant and keeps only Bootstrap overrides
that T6 deletes. Also owns a Go test, placed next to the code that loads `cmd/web/client/html`, that fails
when a hook from the list above disappears from the templates. No template changes.

### T1

Owns `header.html`, `header--links.html`, `footer.html`, `toaster_controller.js` and `toast_controller.js`
(toast markup without Bootstrap classes, with a real close button), and `e2e/browser/layout_test.go` and
`navigation_test.go`. The nav follows the canvas: logo and wordmark, Feed / Explore / Controls, Write as the
primary button, the username linking to settings. On phones it collapses behind a menu button driven by the
existing `toggle` controller. The GitHub link moves to the footer.

T1 also owns `partial--editor-toolbar.html` and the toolbar styles in `_components.scss`. The comment form
(T2) and the post editor (T4) share the toolbar, so it has to be done before both. Its items become real
`<button>`s with `aria-label`s and inline SVG icons instead of `<i role="button">`, keep their
`data-command`s, and appear as a row at the top of the box that holds the textarea (see the canvas). Comments
get bold, italic, link, quote, list, code and image upload; posts add cut, spoiler and gallery.
`mdeditor_controller.js` changes only if it selects the old markup.

### T2

Owns `feed.html`, `user_home.html`, `index.html`, `single_post.html`, `shared_post.html`,
`partial--post-item.html`, `partial--feed-items.html`, `partial--post-list.html`, `partial--load-more.html`,
`partial--feed-prompts.html`, `form--comment.html`, `form--post-prompt.html`, `_posts.scss`, the image classes
pkg/markdown emits (`mx-auto d-block` on standalone images, replaced by pcom classes styled in `_posts.scss`,
goldens updated), and `e2e/browser/feed_test.go`, `comments_test.go`, `journal_paging_test.go` and
`index_test.go`. Every `us-*` hook stays on the element it marks today. Comment, reply and edit keep their
`toggle` behavior; only their markup changes to the action row and the in-place box, with T1's toolbar
at the top of the box. The public-link line
keeps its `action` controller calls (`create_share`, `delete_share`) and adds copy through the `clipboard`
controller.

### T3

Owns `settings.html`, `form--settings-*.html`, `partial--settings_*.html`, `partial--success-message.html`,
`partial--error-message.html`, `form--send-invite.html`, `_settings.scss`, the settings handlers in
`pkg/web/app/routes_settings.go` and the page constructor in `pkg/web/pages_accounts.go`, and
`e2e/browser/settings_test.go`. The contract: each form swaps itself (`hx-swap="outerHTML"`, as user styles
already do) and renders its status slot as saved or not saved. The API key, private feed URL, remove-feed and
invite actions return their section's partial instead of reloading the page (`skipReload` with an
`hx-target` on the section). Handlers stay thin: they bind, call the service and render. A browser test per
section asserts what the user sees after saving and the stored state.

The RSS feeds section covers its error states as the canvas shows them. A feed whose last fetch failed shows
"The last fetch failed" in the error color, with the error text in a disclosure. A feed that has never been
fetched says so. A rejected URL shows its message under the field. Adding a feed re-renders the section in
place; today it is `FormSaveFullReload` in `pkg/forms/form_add_feed.go`, which T3 also owns. The About field
uses T1's toolbar in the same box as the comment form.
