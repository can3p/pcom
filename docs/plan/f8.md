## F8 — One visual language for pcom (#209)

Status: running · Depends on: — · Branch: `feat/f8-design`

The app looks like stock Bootstrap. Fonts vary from page to page, and every page invents its own controls: edit
is a link in the feed, an icon on a post and a button on a comment. One settings form reloads the page, another
shows a toast, a third shows an inline message. This wave replaces that with a small design system of our own:
tokens, a type scale and a few components. Every page uses it, and Bootstrap goes away.

The design comes first and is made in Claude Design:
[pcom redesign canvas](https://claude.ai/artifact/6rkD8VEnriQeyFyxkRRBtG) (private to the owner). It has
the foundations sheet, the current site for reference, and mockups of the feed, a single post with comments
(desktop and phone), settings and the editor. Every page artboard has a Dark tweak. The owner approved the canvas on 2026-10-04. It is the reference for
every task; a later comment on it is folded into the canvas first, then into this file.

Decided on 2026-10-04:

- **Bootstrap is dropped**, CSS and icon font both. pcom uses only its CSS (no Bootstrap JavaScript;
  `data-bs-dismiss` on the toast is dead markup). That CSS is mostly utilities (`mt-*`, `d-flex`, `col-*`),
  `card`, `btn`, `form-control` and `alert`, and the redesign replaces all of them anyway.
- **User CSS hooks stay stable.** User CSS is loaded on the journal, single post, feed and explore pages,
  inside `.user-styles-applied`. Its contract is the `us-*` classes, and they keep their names and meanings:
  `us-user-home`, `us-user-header`, `us-profile-about`, `us-feed-post`, `us-feed-post-stats`,
  `us-feed-comment`, `us-feed-rss-item`, `us-post-date`, `us-load-more`, `us-single-post`, `us-post-header`,
  `us-post-body`, `us-public-link`, `us-comment-stats`, `us-comments-section`, `us-single-comment`,
  `us-comment-form`. The other classes (Bootstrap's and pcom's own) can change. Today the guide doesn't list the hooks; T7 documents them.
- **The project website (`website/`) is out of scope.** It has its own stylesheet and stays as it is.
- **Paper colors.** The light theme is warm paper (`#FAF6EE`) with brown-olive ink and olive links. The dark theme
  is warm brown-black (`#1F1C17`) with cream titles and sage links, not white on black. There is no orange
  accent (cream with orange reads as Substack); the mascot's orange stays in the logo only. The values are on the
  canvas's Paper direction board and in its page boards.
- **Cyrillic is a must.** Posts are written in Russian as well as English, so the text face must have
  Cyrillic. That rules out Archivo, the font of the chosen direction.
- **Golos Text, and the system monospace.** Golos Text is a Cyrillic-first grotesque with weights 400–900. It is
  used for titles (800, tight) and for reading and interface text. (Onest and Manrope were
  compared on the canvas's Font tweak.) The system monospace (`ui-monospace`, SF Mono, Menlo, Consolas) is used for navigation,
  item actions, link-post sources and small labels. Golos Text has no italic, so bylines are upright, and
  `<em>` in posts renders as the browser's synthesized oblique. Golos Text is self-hosted through
  `@fontsource/golos-text`, so the CSP stays as it is: fonts load from `default-src`, which is self and the
  static CDN. The monospace costs no download (see Speed).
- **The single post's title has an accent bar under it**, as on the canvas's post boards.
- **Speed is a requirement.** The site must open fast on a first visit, so the pages have a byte budget that a
  test enforces (see Speed).

### Speed

Measured on the current production build (`yarn production`, gzip -9):

| Asset | Today | Budget after F8 |
|---|---|---|
| CSS | 329 KB, 49 KB gzipped (Bootstrap included) | 25 KB gzipped |
| Icon font | 134 KB woff2 (Bootstrap Icons), fetched on every page for the header's GitHub icon | none: inline SVG |
| Text fonts | none (system fonts) | 40 KB preloaded; 70 KB at most per page |
| JS | 45 KB gzipped | unchanged |

Font rules, from measuring `@fontsource/golos-text` 5.3 (Latin / Cyrillic, per weight):

- **Static woff2 files, three weights, each split into subsets by `unicode-range`:** 400 (12.0 / 7.0 KB),
  600 (12.3 / 7.1 KB) and 800 (12.7 / 7.3 KB). That is 58 KB for all of them. A page fetches only the faces and
  subsets its text uses. latin-ext (7 KB) and cyrillic-ext (5 KB) are separate faces that load only when such a
  character appears. No 500 or 700: CSS uses only 400, 600 and 800. No woff, no Vietnamese.
- **Latin and Cyrillic 400 and 800 are preloaded** from `header.html` (`<link rel="preload" as="font"
  type="font/woff2" crossorigin>`), by their hashed names from the webpack manifest: 39 KB. Cyrillic is
  preloaded because Russian posts are expected; without the preload, Cyrillic text would swap in late. 600 loads
  on use.
- Archivo, measured for comparison, is 14–16 KB per weight for Latin alone and has no Cyrillic.
- **`font-display: swap` with a metric-matched fallback:** an `@font-face` over a local Arial/Helvetica with
  `size-adjust`, `ascent-override` and `descent-override` computed for Golos Text. The swap then barely moves the
  text.
- **The monospace is the system's:** JetBrains Mono would add 21 KB per weight for 13 px labels.
- Fonts and CSS are served from `/static` with the existing immutable cache header.

The budget is enforced by a browser test (T6), `TestFirstVisitWeight`. It opens the feed and a single post in
a fresh browser context and sums the encoded bytes of the CSS, font and JS responses against the budgets
above. The budget values are constants in that test, each with the reason for its number.

### The design system in short

The canvas's Foundations artboard is the reference. The rules a task must keep:

- **Tokens** are CSS custom properties on `:root`, redefined for dark mode (the
  `prefers-color-scheme` media query, and `[data-bs-theme="dark"]`, which T6 renames to `[data-theme="dark"]`). Ground,
  surface, sunken, line, text, muted, accent (text and links pass 4.5:1), and a separate title color, ok, err. Spacing
  is 4/8/12/16/24/32/48/64; radius is 8 for controls and 12 for boxes.
- **Type**: Golos Text for reading (18–19 px, line height 1.65, a 680 px column), for titles (800) and for the
  interface (15 px; 14 px for metadata; 600 for labels and buttons). The system monospace at 13 px for
  navigation and actions.
- **Content is not boxed.** Posts, comments and feed items sit on the ground, separated by space and
  hairlines. A box is only for a form that opens in place, such as the comment composer or a comment being
  edited.
- **Item actions are one row of quiet text links** under the item: muted, one size, one order (comments,
  reply, edit, share, delete). There are no icon-only actions and no buttons inside content. A link post shows
  its URL as one muted line under the byline. A public link is one muted line under the actions
  (copy, turn off).
- **Buttons come in one size.** Primary marks the one main action of a form; every other button is
  secondary; destructive ones are secondary in red and always confirm.
- **Every form saves in place** and reports next to its submit button (saving / saved / not saved). Field
  errors sit under the field. There are no page reloads after a form, and no toasts for form results. Toasts
  remain only for results of actions that have no form, and they get pcom's own markup.
- **Settings is one column** with a section list on the left that stacks on phones.

### Structure of the work

New SCSS lives in `cmd/web/client/scss/`. It is split so that page tasks own disjoint files:

- `_tokens.scss` holds the custom properties, light and dark, and the font faces.
- `_base.scss` holds the reset, element defaults and `.prose`.
- `_components.scss` holds the shared classes: `.btn`, `.field`, `.meta`, `.acts`, `.item`, `.box`,
  `.status`, `.nav`, `.toast`.
- One partial per area: `_posts.scss`, `_settings.scss`, `_editor.scss`, `_auth.scss`, `_controls.scss`.

Until T6, the new classes live alongside Bootstrap, so each page can move on its own and the tree keeps
working. T0 creates every file (the area partials empty) and imports them; after that, each task edits only
its own partial.

fetched says so. A rejected URL shows its message under the field. Adding a feed re-renders the section in
place; today it is `FormSaveFullReload` in `pkg/forms/form_add_feed.go`, which T3 also owns. The About field
uses T1's toolbar in the same box as the comment form.
