## F14 — Per-client rate limits

Status: planned · Depends on: — · Branch: `feat/f14-rate-limits`

No single client can overload pcom. Today every limit is per account or per mailbox (login codes, the
subscription caps) or site-wide (proofreading, the subscription brake), and fly's only bound is a soft limit
of 20 concurrent requests. A script that loops over the public pages, or posts the anonymous forms as fast
as it can, meets nothing per client. This wave adds an in-process limit per client IP, with a strict allowance
for anonymous writes and a generous one for reads.

Decided on 2026-11-06:

- **The client IP comes from the platform only.** gin trusts `X-Forwarded-For` from anyone by default, so
  the `client_ip` pcom logs today can be forged by the client. A setting `CLIENT_IP_HEADER` sets gin's
  `TrustedPlatform` (`Fly-Client-IP` in production, through `fly.toml`'s `[env]`); empty, the socket address
  is used, which is what local development and the tests see. The request log uses the same value.
- **Two classes, both per IP.** Anonymous writes (the subscribe and lost-link forms, the confirm and
  unsubscribe POSTs, login and signup posts, the waiting list) get `RATE_WRITES_PER_MINUTE` (10) with a burst
  of `RATE_WRITES_BURST` (5). Every other request from a client that isn't logged in gets
  `RATE_READS_PER_MINUTE` (300) with a burst of `RATE_READS_BURST` (60). Past either, the answer is `429`
  with `Retry-After`.
- **Logged-in users and API keys are not limited per IP.** Their account limits apply, and a shared office
  or carrier IP mustn't lock members out. The limiter runs after the session and API-key middleware, so it
  knows who is asking.
- **In memory, bounded, per machine.** `golang.org/x/time/rate` limiters in `hashicorp/golang-lru/v2`
  (already a dependency), at most `RATE_TRACKED_CLIENTS` (10000) IPs; the least recently seen is dropped. No
  database write per request. With more than one machine each keeps its own allowance, which is still a bound.
- **What a throttled visitor sees**: a full page "Too many requests. Try again in a minute." for a page
  load, the form's own error slot for an htmx form post (the same `status err` the forms use), and the
  JSON error shape for `/api`.
- **Everything stays testable locally, offline** (`docs/architecture.md`): the defaults are far above what
  a developer clicking around does, so compose sets nothing; the E2E harness raises all four limits so
  parallel tests from one IP aren't throttled, and one test lowers them on its own server.
