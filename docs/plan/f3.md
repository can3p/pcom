## F3 — Public profile section on the blog page (planned, #186)

A user writes a free-form "About" text in their settings; it is shown at
the top of their journal (`/users/:username`, `user_home.html`) when it is
not empty. Markdown, with the same controls and the same rendering rules as
a comment, but defined separately so the two can diverge later.

Decided by this plan (Q19 in `docs/open-questions.md` lists what the owner
should confirm):

- **Storage:** a new table `user_profiles (user_id uuid primary key
  references users on delete cascade, about text not null, updated_at
  timestamp not null)`, like `user_styles`. Not a column on `users`: the
  user row is loaded on every request, and a profile table is where later
  profile fields go.
- **Who sees it:** whoever may open the journal; the journal's own
  visibility rules (`reading.Journal`, `CanSeeProfile`) already decide.
  Nowhere else: not in the public RSS feeds, the feed or explore.
- **Validation:** `accounts.ValidateProfileAbout`, its own function with
  the comment's limit today (at most 6,000 characters). An empty text is
  valid and removes the section (the row is deleted). Whitespace only
  counts as empty.
- **Rendering:** a new view type `types.ViewProfile` and template function
  `markdown_profile`. In `pkg/markdown` it gets its own `case` wherever
  `ViewComment` has one, with the same behavior, never a shared alias.
- **Settings:** a new card "Public profile" on the settings page, with the
  comment form's controls (`mdeditor` toolbar, image upload into the user's
  media), saved by its own form.
