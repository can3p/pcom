## F12 — Bounces and complaints

Status: planned · Depends on: — · Branch: `feat/f12-mail-suppression`

pcom stops mailing addresses that bounce for good or mark its mail as spam, whatever provider delivers it.
Email subscriptions make pcom mail people without an account, so a complaint about those mails must end their subscription
rather than hurt the domain's reputation.

Decided on 2026-11-05:

- **Nothing in pcom knows the provider.** pcom has a suppression list and a neutral feedback event; a
  provider's webhook is turned into those events by an adapter that lives in `can3p/gogo` next to its sender
  (`sender/mailjet`). Changing provider is one adapter and one setting, with no change to pcom's tables,
  services or mails.
- **Suppression never blocks access.** Mails a person asks for at that moment to get into their own account,
  `login_code` and `confirm_signup`, are always sent. Every other mail to a suppressed address is dropped,
  including `subscriber_confirm` and `subscriber_manage_link`, since anybody can type the address.
- **A complaint about a subscriber mail** deletes every subscription of that address, and each author gets
  the usual `author_subscriber_left` mail. A complaint about any other mail suppresses the address.
- **A hard bounce** suppresses the address; soft bounces and deferrals are the provider's retries and are
  ignored.
- **The operator lifts a suppression** with `web admin unsuppress --email`; there is no user-facing page.

### Design

Mail is sent by River jobs (`pkg/jobs`): a mail job renders its envelope when it runs, and
`deliverer.send` (`pkg/jobs/mail.go`) records the mail in `sent_emails` and hands it to the gogo sender in one
transaction. Both mail workers (`mailWorker`, and `renderedMailWorker` for mails rendered before the queue)
go through it, so it is the one place that sees every mail just before it leaves.

- `suppressed_addresses (email_canonical, reason hard_bounce|complaint|manual, source, detail, created_at,
  updated_at)`, unique on `email_canonical`; a second event updates `reason`, `source` and `detail`. The key is
  `emailaddr.Parse(address).Canonical`, the same mailbox key the subscription caps use.
- `pkg/mail` marks each declared mail as `Requested` (always sent) or not, in `declare`, so a new mail has to
  choose; `login_code` and `confirm_signup` are the requested ones. `mail.Requested(emailType) bool` answers
  by email type, because `renderedMailWorker` has only the type.
- **The send checks suppression**: `deliverer.send`, inside its transaction and before recording, looks up the
  canonical address of every recipient; for a mail that isn't requested and goes to a suppressed address it
  records the row with `sent_emails.suppressed_reason` set (a new nullable column), sends nothing, logs the
  reason, and the job completes without a retry. The row keeps a re-run of the job from sending later, and
  shows the operator what was held back. Checking when the job runs, not when it is enqueued, also stops
  mail enqueued before the event arrived.
- **Feedback events**: `feedback.Event{Kind hard_bounce|complaint, Address, MessageID, Detail, At}` and
  `feedback.Parser` (`ParseWebhook(*http.Request) ([]Event, error)`), defined in gogo next to `sender.Mail`;
  the Mailjet parser maps `bounce` with `hard_bounce: true` and `spam` (TG checks the event schema against
  Mailjet's current documentation).
- **Webhook route**: `POST /hooks/mail-feedback`, outside sessions and CSRF, authorized by HTTP basic auth
  against `MAIL_FEEDBACK_SECRET` (`settings.Secret`; the route is off when it is empty). The provider is
  `MAIL_FEEDBACK_PROVIDER`, a choice of the parsers compiled in (`mailjet` for now). The handler parses and
  enqueues one `mailfeedback.event` job per event, which records what happened and does nothing per address
  in the request ("the request records what happened; a job decides who hears of it",
  `docs/architecture.md`). It answers 200 to any authorized request, so a provider doesn't retry a payload
  pcom can't use, and logs what it skipped. The job's unique key is provider + message id + kind, so a
  provider's retried webhook doesn't apply an event twice.
- **Matching a complaint to a mail**: gogo's sender returns the provider's message id
  (`sender.Sender.Send` gains a result, or a new `SendWithID`; TG decides, keeping gogo's other users
  compiling), and `deliverer.send` stores it in `sent_emails.provider_message_id` (new, indexed) in the same
  transaction. The event worker finds the mail's `email_type` by it; a complaint whose mail isn't found
  suppresses the address.
- **A complaint about `subscription_post`** calls a new `subscriptions.EndForAddress(ctx, tx, canonical)`,
  which deletes every subscription of that mailbox through the existing unsubscribe path, so each author gets
  `author_subscriber_left` (its job carries the address, since the subscriber row is gone when it runs). Any
  other complaint, and every hard bounce, upserts `suppressed_addresses`.
- **Tests** stub the provider side only: webhook payloads are JSON files under the adapter's `testdata/` in
  gogo, and pcom's E2E test posts a neutral fixture through a test parser registered by the harness. pcom's
  `fakesender` returns a message id per mail, so tests can post feedback for a mail they caused.
