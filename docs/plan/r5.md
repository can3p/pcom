## R5 — bun and pgx instead of sqlboiler

Status: running · Depends on: — · Branch: `refactor/r5-bun`

Replace sqlboiler (code generated from a live database) with
[bun](https://github.com/uptrace/bun) over [pgx](https://github.com/jackc/pgx)'s `database/sql` driver,
and the generated `core` structs with model structs pcom writes itself. Behavior is unchanged.

### Decisions

- **bun, not bob or sqlc** (owner, 2026-10-05). bob is still v0.x with breaking minor releases and keeps the
  code generation, the codegen database in `generate.sh` and the generator pin in the tools image. sqlc is
  code generation too, handles runtime filters and eager loading worst, and gives every query its own row
  type. bun needs no code generation and covers what the repositories use: a query builder for runtime
  filters (`Page.mods`, optional filters), relation loading, upsert and `FOR UPDATE`.
- **Q13 is answered yes.** Repositories return pcom-owned types from `pkg/model`. These structs *are* the
  bun models: their `bun` tags are inert outside `pkg/repo`, so there is no separate mapping layer. Only
  `pkg/repo`, `pkg/model` and the test factories import bun (the arch test enforces it). wave-close moves
  this rule to `docs/architecture.md`.
- **Model conventions** (S1 writes them; every later task follows them):
  - one file per area in `pkg/model` (package `model`); struct and field names as sqlboiler named them
    (`Post.UserID`, `Post.PublishedAt`), so templates and most callers keep their field names;
  - a nullable column is a pointer (`*string`, `*time.Time`); `volatiletech/null` goes away. Go 1.26's
    `new(expr)` replaces `null.StringFrom(x)` and `null.TimeFrom(x)`;
  - enums keep sqlboiler's type and constant names (`model.PostVisibilityPublic`), plus the helpers callers
    use (`AllPostVisibility`, `IsValid`). A nullable enum is a pointer to the enum type;
  - a relation is a plain field named like sqlboiler's `R` field (`post.R.User` becomes `post.User`),
    except where that collides with a column field. S1 lists every rename in a comment at the top of
    `pkg/repo/convert.go`;
  - a column with a database default is tagged so that a zero value inserts `DEFAULT` and the value comes
    back after insert.
- **Schema drift is a test, not codegen.** A test in `pkg/model` compares every model with
  `information_schema` on the test database: same column set, nullable column ↔ pointer field, defaulted
  column ↔ default tag, every table has a model. It replaces CI's "Generated models are current" job.
- **One driver everywhere.** The server, the CLI commands and the test databases connect through pgx.
  gogo's `testcontainers/postgres` opens its databases with lib/pq; `pkg/testutil/testdb` reopens each one
  with pgx from `TestDB.URL`, so tests run on the production driver. (A `WithDriver` option in gogo would
  remove the reopen; that is a gogo change, not part of this wave.) lib/pq stays in `go.mod` only as
  gogo's indirect dependency.
- **Two passes, because the types form one graph.** User, Post, PostComment, PostShare, PostPrompt and the
  connection types load each other as relations, so no repository file can switch types alone. Pass B swaps
  the types at the repository boundary and keeps the sqlboiler queries, converting with a throwaway
  reflection helper; the existing tests prove the swap. Pass C then rewrites the queries file by file in
  parallel, with every test already on the new types. D deletes sqlboiler.

### Constraints

- gogo takes no executor since v0.1.0. The mail queue is pcom's `repo.MailQueue` (with
  `pkg/mail/sender/dbsender` and `pkg/testutil/fakesender`); it converts like any other repository.
- Every query stays in `pkg/repo`. Repository method names and semantics don't change. Services and
  handlers change only for the types (`*core.User` → `*model.User`, pointers, relation fields).
- Queries run on whatever executor the `Store` holds (database or transaction), through bun's
  `.Conn(exec)`. So `repo.Using(exec)`, the factories' `exec` parameter and every test call site
  (`factory.User(ctx, db)`) keep their shape. D renames `boil.ContextExecutor` to `repo.Executor`, an
  interface with the three `...Context` methods.
- **`e2e/` exception.** R-waves don't edit `e2e/`, but `e2e/` and `e2e/browser` import `core` (mostly the
  visibility enum constants). R5 may change their imports, type names and null-to-pointer expressions, and
  nothing else: `git diff -- e2e | grep -E '^[-+].*(require|assert|Expect)\.'` shows only lines whose
  edits are type renames.
- Tests that use sqlboiler directly (`core.X(...)`, `x.Update(ctx, db, boil.Infer())`, `qm.` filters) are
  rewritten in pass B by the task that owns their package. Today they are in `pkg/web`,
  `pkg/service/{posts,feeds,shares,reading,accounts}`, `pkg/testutil/ginctx`, `pkg/repo` and
  `pkg/mail/sender/dbsender`. They become factory or repository calls (ground rule 1, `docs/testing.md`).
- F7 adds repository methods. Whichever of F7 and R5 merges second converts or rebases them.
- No unique-violation detection exists today (`grep -rn 23505 pkg` is empty), so the driver change can't
  silently break one. A new one checks `*pgconn.PgError` code `23505`.

### S0 — Driver swap

The tree stays on sqlboiler; only the driver changes, so a regression here is the driver's.

- `go.mod`: add `github.com/jackc/pgx/v5`. `cmd/web/db.go` and `repo.ConnectPostgres` (`pkg/repo/comments.go`)
  connect with `sqlx.Connect("pgx", ...)` after a blank import of `github.com/jackc/pgx/v5/stdlib`; drop the
  lib/pq imports in `cmd/web/main.go` and `pkg/repo/comments.go`.
- `pkg/testutil/testdb`: reopen `TestDB.DB` and `TestDB.SQL` with pgx from `TestDB.URL` and close them in a
  `t.Cleanup` registered after gogo's, so it runs before the database is dropped.
- Run `make check-q` and `make test-ui`. Driver differences to look for: the time zone of scanned
  timestamps (golden files, `renderHumanTime`), enum and `jsonb` (`outgoing_emails.payload`) scanning.
  Fix them in the driver setup, not in callers.

### S1 — bun plumbing and the models

Contract work, by the coordinator. No caller changes yet.

- `go.mod`: add `github.com/uptrace/bun` and `bun/dialect/pgdialect`.
- `pkg/model`: every table's struct and enum, following the conventions under "Decisions". `make model T=X`
  gives sqlboiler's fields and relations to copy.
- The drift test (see "Decisions") in `pkg/model`, on `testdb`.
- `pkg/repo`: the `Store` keeps its executor and builds bun queries with `.Conn(s.exec)`; a helper the
  factories use too (`repo.Query(exec)` or similar; pick the name once).
- `pkg/repo/convert.go` (deleted in D): generic, reflection-based `core` ↔ `model` copying by field name,
  null types ↔ pointers, `R` relations ↔ relation fields through the rename list at the top of the file.
  Its test fills every field and relation of every `core` type with non-zero values and checks that a
  round trip loses nothing.
- Spike tests in `pkg/repo` that pin the bun behaviors pass C relies on, kept as regression tests:
  - a has-many relation loaded through `.Conn(tx)` sees rows inserted earlier in the same transaction;
  - `FOR UPDATE` with a loaded belongs-to relation needs `FOR UPDATE OF <table>` (bun joins it with a
    `LEFT JOIN`, and Postgres refuses to lock the nullable side);
  - `bun.In` with an empty slice matches nothing and isn't a syntax error (`PublishedPostsOfUsers` with an
    empty `someOf`);
  - a zero defaulted column inserts its default and reads back after insert; an enum and a `jsonb` value
    round-trip;
  - a limit on a loaded has-many relation applies across all parents, as sqlboiler's `qm.Load(..., qm.Limit(1))`
    did (`RSSFeed` subscriptions).
- `pkg/arch`: add bun and pgx to `ormPackages`; `pkg/model` may import bun.

Write the outcome of each spike (how to lock, how to express an empty `IN`, which tags a defaulted column
gets) as a short "Writing bun queries" section in `docs/architecture.md`. C tasks follow it.

### B1 — Repository boundary and factories

Owns `pkg/repo` (except `convert.go` and the spike tests), `pkg/testutil/factory`, `pkg/feedops/testutil`
and `pkg/pgsession`.

- Every exported `Store` method and function in `pkg/repo` takes and returns `model` types
  (`core.PostSlice` → `[]*model.Post`). Reads keep their sqlboiler query and convert the result. Writes
  convert to `core`, run the sqlboiler write and copy the result back into the caller's struct, so
  database defaults still reach it.
- The factories insert and read `model` structs with bun directly (`.Conn(exec)`), keeping their names,
  options and parameters. `ListOutgoingEmails(filter ...qm.QueryMod)` takes a typed filter instead.
- `pkg/pgsession` loads the current user as `*model.User`.
- Done when `make vet-q PKG=./pkg/repo/... ./pkg/model/... ./pkg/testutil/factory/... ./pkg/feedops/testutil/... ./pkg/pgsession/...`
  passes and `make test-q PKG=./pkg/repo/... ./pkg/model/... ./pkg/testutil/factory/...` passes. The
  rest of the tree doesn't build yet.

### B2 — Mechanical sweep

A script the coordinator runs over every package that imports `core`, outside `pkg/repo`, `pkg/model` and
the B1 packages:

- the `core` import becomes `pkg/model`, and `core.X` becomes `model.X` for each X that exists in `model`;
- `core.XSlice` becomes `[]*model.X`;
- `.R.<Name>` becomes `.<Name'>` from the rename list in `convert.go`;
- `null.StringFrom(` and `null.TimeFrom(` become `new(`.

What the script can't do (`.Valid` checks, `.String` and `.Time` reads, nil handling, tests that used
sqlboiler directly) is B3 and B4. The sweep is committed together with them.

### C1–C6 — Queries to bun

One task per row of the table, in parallel, each in its own worktree (`isolation: "worktree"`, first command
`git merge --ff-only refactor/r5-bun`; push the branch before dispatch). Each task owns only its files
in `pkg/repo` and their tests in `pkg/repo`; C6 also owns `dbsender` and `fakesender`.

- Every query in the owned files becomes a bun query following "Writing bun queries" in
  `docs/architecture.md`. Method signatures and semantics don't change: same filters, order, limits, locks
  and loaded relations.
- Done when the owned files import neither `core`, `qm`, `boil` nor `convert.go`'s helpers, and
  `make check-q` passes in the worktree. No test outside `pkg/repo` is edited: the existing service, web
  and E2E tests are what prove the rewrite.
- C1–C3 are strong because they hold the visibility and permission queries (published posts by
  visibility and profile, the connection graph, whitelists, mediation, shares). A wrong filter there leaks
  a post, and only some of those cases have a test. Mutation-check one visibility filter per task.
