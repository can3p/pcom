## F7 — Translating posts and RSS items to English (planned, #144)

A reader can translate a post or an RSS item into English with a cheap
model, see the original again at any time, and ask for every post in a
given language to be translated for them ("I don't read German"). The
markdown structure stays intact; only the text is translated. Translations
are cached and shared between readers, refreshed when a post is edited,
and never made for drafts.

**Do not start before Q26 and Q27 in `docs/open-questions.md` are
answered.** Q25 is decided: the author allows translation per post. The
defaults below are what the tasks build if the owner accepts them.

- **The author decides (Q25, decided 2026-10-01).** A post is translatable
  only if its author ticked "Allow readers to translate this post" in the
  editor: a new column `posts.allow_translation boolean not null default
  false`, so no existing post is sent anywhere until its author opts in. The
  API (`blg`) takes an optional `allow_translation`; leaving it out keeps
  the stored value (documented in `docs/api.md`). Turning it off deletes the
  post's cached translations and queued jobs. RSS items have no pcom author
  and are already public, so they are always translatable.
- **Who can trigger a translation:** a logged in user, for a published
  post or an RSS item they can read now (the reading service's rules). An
  anonymous visitor sees no translate control and the route refuses them,
  so outsiders can't spend the budget. Drafts and edit previews are never
  translated.
- **Budget:** a per-user limit of new (uncached) translations per day and a
  site-wide daily limit, both settings; a cached translation costs nothing
  and isn't counted. Over the limit, the reader sees "Translation is not
  available right now" and the original. With no API key configured the
  feature is off: no controls, no settings card.
- **Model:** Claude Haiku 4.5 (`claude-haiku-4-5`) through the Anthropic Go
  SDK (`github.com/anthropics/anthropic-sdk-go`), behind a
  `translate.Translator` interface so tests use a fake and the provider can
  change (Q26). The implementer loads the `claude-api` skill before writing
  the client.
- **Structure:** the text is never sent as a document. `pkg/markdown`
  extracts the translatable text runs from the goldmark AST (paragraph and
  heading text, emphasis, link text, image alt, list items, table cells),
  leaving out code, URLs, `@handles`, block tags (galleries), embedded
  videos and HTML. The runs go to the model as a JSON array and come back as
  an array of the same length, and are put back at their byte offsets; a
  response of the wrong shape is an error, not a partial translation. RSS
  items are sanitized HTML, so their text nodes are extracted with
  `golang.org/x/net/html` the same way. The subject or title is one more
  run.
- **Language detection** is local and free (Q27): a Go library run when a
  post is published or edited and when an RSS item is imported, stored in
  a `language` column (ISO 639-1, null when unsure). Detection decides
  whether to offer "Translate from German" at all; content already in
  English gets nothing.
- **Cache:** a table `translations (source_kind post|rss_item, source_id,
  target_lang, source_hash, subject, body, created_at)`, unique on
  `(source_kind, source_id, target_lang)`. `source_hash` is the SHA-256 of
  the source subject and body; a row whose hash no longer matches is stale.
  Deleting a post deletes its translations (cascade).
- **Edits:** saving a published post whose translations exist re-translates
  them in the background (a queue row picked up by a worker, the way mail
  is sent), so the next reader gets a fresh one; until then a stale
  translation is not shown, the reader sees the original and "Translation
  is being updated". This is "translation should be updated on post edits"
  without making the author wait on the model.
- **Preferences:** a settings card "Translation" with the languages to
  always translate (a multi-select of the detected languages; target is
  English only for now, stored per user so another target is a later
  change). For those languages, posts and RSS items load translated, with
  "Show original" one click away. Otherwise a "Translate" button loads the
  translation in place (htmx), with "Show original" next to it.
- **Scope:** posts (feed, single post, journal, explore) and RSS items in
  the feed. Not comments, not profiles, not RSS outputs.
- **Privacy:** the privacy policy (`cmd/web/client/articles/privacy_policy.md`)
  says that a post whose author allowed translation, and RSS items, are
  sent to the model provider when a reader asks for a translation.

### T1

Owns a new `pkg/markdown/translate.go` with tests and goldens under
`pkg/markdown/testdata/translate/`, and a new `pkg/postops/rss/translate.go`
(HTML text nodes) with tests. Pure functions: `Segments(source) []string`
and `Apply(source, translated []string) (string, error)`. Goldens cover
every construct in the structure rule above, including nested emphasis in a
link and a gallery block tag, and the round trip
`Apply(src, Segments(src)) == src`.

### T2

Owns `pkg/service/translations/` (T0's skeleton: the service, the worker
for the jobs, and the table test) and a new `pkg/repo/translations.go`. `Translate(ctx, actor, kind, id) (*Result,
error)`: needs an actor; the reading service decides whether they may read
the source (`ErrNotFound` otherwise, a draft included); a post whose
author didn't allow translation is `ErrForbidden`; cache hit with a
matching hash is returned without counting; otherwise the limits are
checked, the translator is called, the row stored. `RetranslateStale(ctx,
postID)` queues the jobs. Table test: anonymous, a reader who may not see
the post, a draft, a post that doesn't allow translation, a cached hit (the fake is not called), a stale cache
(not shown, re-translated), each limit, a translator error (nothing
stored, nothing counted), an RSS item of a feed the reader isn't
subscribed to.
