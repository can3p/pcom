## R7 — Structured logging with zap (planned, after RS and R2)

Replace the three ways the code logs today with one
[zap](https://github.com/uber-go/zap) `*zap.Logger`. Counted on 2026-09-29,
outside tests and generated code: 26 calls to the standard `log` package, 24
to `log/slog`, and 17 `fmt.Print*` calls, spread over `cmd/web`,
`pkg/forms`, `pkg/media/server`, `pkg/feedops`, `pkg/mail`, `pkg/auth`,
`pkg/markdown` and `cmd/scripts`.

Why after RS and R2: RS moves most of the code that logs into services, so
converting earlier means converting it twice. R2 brings the go-flags
configuration where the log level and format belong. R7 can run alongside
R4 and R5 only if the tasks own disjoint files.

Rules for the converted code:

- The logger is passed explicitly: to constructors of long-running workers
  (feed poller, mail sender, media server), and through the request context
  for handlers and services. No `zap.ReplaceGlobals`, no package-level
  logger.
- Structured fields, not formatted strings:
  `logger.Error("send failed", zap.Error(err), zap.String("mail_id", id))`.
- An error is either returned or logged, never both. It is logged once, at
  the boundary that handles it (the request middleware, the worker loop).
- `fmt.Print*` remains only for a CLI subcommand's output to its user.

| Task | Tier | Owns | Notes |
|---|---|---|---|
| L0 | strong | `pkg/logging` (new), the gin middleware setup in `cmd/web`, the config option, `pkg/testutil` log helpers | Build the logger from config: console encoder in development, JSON in production, level from a flag. A request middleware that puts a request-scoped logger (request ID, user ID once known) into the context and logs each request, replacing gin's logger. Recovery logs a panic with its stack. A test helper around `zaptest/observer`, so tests can assert on log entries. Contract work: the coordinator does it. |
| L1 | mid | `pkg/feedops`, `pkg/mail` (including `sender/dbsender`), `pkg/media/server` | Workers take the logger in their constructors. |
| L2 | mid | `pkg/service/*`, `pkg/forms`, `pkg/auth`, `pkg/markdown` | Take the logger from the context. The goldmark transformers can't return errors, so they log through a logger passed to the renderer. |
| L3 | cheap | `cmd/scripts`, CLI subcommands | Logs go through zap; user-facing output stays `fmt`. |
| L4 | cheap | `.golangci.yml`, the `pkg/arch` test | Forbid importing `log` and `log/slog` outside `pkg/logging` (depguard), so the old styles can't come back. |
