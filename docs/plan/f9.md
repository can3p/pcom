## F9 — Grammar check and style review in the post editor

Status: planned · Depends on: an Anthropic API key; WireMock test helper (task TM, shared with F7) · Branch: `feat/f9-proofread`

The post editor gets two buttons, **Check grammar** and **Style review**. Both send the post's subject and
body to Claude through the pcom server and show the result in a panel beside the editor:

- **Grammar check** returns concrete fixes (spelling, punctuation, grammar, word choice). The author applies
  or dismisses each one; nothing changes in the text without a click.
- **Style review** returns notes on style, logic and pacing, aimed at short fiction and essays. Notes are not
  fixes: the author marks each one done or keeps the text as is, optionally saying why. Reviews are kept per
  post, so the next review knows what was said before, what the author did and why.

### Terms

The plan uses these words in one sense each:

| Term | Means | Where it appears |
|---|---|---|
| **proofreading** | the feature as a whole: both kinds below | code and settings only: `pkg/proofread`, `pkg/service/proofread`, `PROOFREAD_*`, `proofread_requests`, the `proofread_*` routes, the `proofread` controller. Users never see the word |
| **grammar check** | one kind: language corrections (spelling, punctuation, grammar, word choice) | the **Check grammar** button, the Grammar tab, the grammar limit |
| **suggestion** | one result of a grammar check: a quoted passage, its replacement and an explanation; it can be applied or dismissed | the Grammar tab's cards; `suggestions` in JSON |
| **style review** | the other kind: feedback on the writing (style, logic, pacing, repetition, the title); it never changes the text | the **Style review** button, the Style tab, the style limit |
| **review** | one stored style review of a post: a summary and notes, numbered per post (review 1, 2, …) | "Review 3 of this draft", **Review again**, **Earlier reviews** |
| **note** | one remark in a review, optionally tied to a passage; it is open, done, kept (as is, with an optional reason) or carried into the next review | the Style tab's cards |
| **request** | one call to Claude of either kind, the unit of the limits and of `proofread_requests` | limits, settings, logs |

"Check" alone always means a grammar check; text that covers both kinds names both.

The design sketch, with clickable screens, is the canvas
<https://claude.ai/artifact/San1jMpSDJT3dS5TfPjZG8>: the grammar panel, the style panel, the panel's states
(waiting for the answer, text changed under a suggestion, limit reached, nothing found, error) and the phone layout.
Russian sample text; English UI.

Decided with the owner on 2026-10-13:

- **Only the post editor.** Not comments, not the profile text.
- **Every logged-in user**, rate limited per user, with **separate hourly limits** for grammar checks and
  style reviews. A grammar check or style review runs only when the user presses its button; nothing runs as they type.
- **Russian is a must**, English too; Claude handles both. Explanations are written in the language of the
  text; the UI stays English like the rest of pcom.
- **The API key stays on the server.** The browser talks only to pcom; no client library sees a key.
- **Start simple:** step 1 (this wave) is a suggestion panel. Underlining every suggestion in the text is a later
  wave; Harper's `lint-framework` (Apache-2.0, `github.com/Automattic/harper`, `packages/lint-framework`) is
  the candidate for it, and this wave's data shape and position tracking are chosen so it fits.
- **Grammar results live on the page only.** Dismissed grammar suggestions are remembered per post in the
  browser's `localStorage`, so a later grammar check doesn't show them again. Iterate later if that's not enough.
- **Style reviews are stored** per post: the text reviewed, the notes, their status and the author's reasons.
- **The subject is part of both kinds.** A grammar fix may apply to the subject; a style note may be about
  the title (clicking it highlights the subject field).
- **Keep as is takes an optional reason**, which the next review reads.

### How it works

**Request.** The browser sends `subject` and `body` as they are in the form (unsaved edits included). The
server does not trust the client for anything but the text: it checks the user, the limit and, for a style
review, that the post is the user's own (`posts.Service.CheckEdit`).

**Grammar check.** One Messages API call, model `PROOFREAD_GRAMMAR_MODEL` (default `claude-haiku-5-5`, effort
`low`), structured output (`output_config.format`, JSON schema below), no streaming. The system prompt is
fixed text embedded in the binary (cacheable); the user message is the subject and the markdown body. The
prompt says: correct only the language; keep the author's style and the text's language; never touch code,
URLs, image syntax or pcom's block tags (`{cut}`, `{spoiler}`, `{gallery}` and their closing tags); explain
each fix in one sentence in the text's language.

```json
{"suggestions": [{"field": "subject|body", "kind": "spelling|punctuation|grammar|word_choice",
  "quote": "exact text to replace", "before": "up to 30 characters right before the quote",
  "replacement": "...", "explanation": "..."}]}
```

**Style review.** One call, model `PROOFREAD_STYLE_MODEL` (default `claude-sonnet-5-5`, effort `medium`),
structured output, no streaming in this wave (the panel shows "Reviewing…"; streaming notes as they arrive is
a later improvement, although the sketch's states screen mentions it). The user message carries:

1. the current subject and body;
2. if the post has earlier reviews: the previous review's subject and body, its notes with their status
   (open, done, kept) and keep reasons, and its summary;
3. the author's "note for the next review", if they wrote one.

Not a replayed conversation: a compact state, cheap and independent of model-side history rules.

```json
{"summary": "what changed since the previous review, or an overall impression for the first one",
 "notes": [{"field": "subject|body|none", "kind": "logic|repetition|pacing|clarity|title|consistency|other",
   "quote": "the passage, verbatim, or empty for a general note", "before": "...",
   "text": "...", "continues": "id of a previous note this one repeats, or empty"}]}
```

**Validating the model's answer** (pure functions, `pkg/proofread`):

- A quote must occur in its field. If `before` is given and `before+quote` occurs, that occurrence is used;
  otherwise the quote's first occurrence; otherwise the suggestion or note is dropped (the model made it up).
- A body quote must not overlap code (blocks and spans), a link or image destination, raw HTML or a block-tag
  line; such suggestions and notes are dropped. `pkg/markdown` provides the protected ranges.
- A suggestion whose replacement equals its quote is dropped; of overlapping suggestions the first is kept.
- The server sends each kept suggestion and note with `occurrence`: how many earlier, non-overlapping matches of
  `before+quote` (or `quote`) there are in the field. It sends **no character offsets**: Go strings count
  bytes, the textarea counts UTF-16 units, and every Cyrillic letter is two bytes, so the browser locates
  `before+quote` itself, taking the occurrence-th match.
- A style note's `continues` must name a note of the previous review; otherwise it is cleared.

**Positions in the browser** (the `proofread` Stimulus controller):

- Each suggestion holds `field`, `start`, `end` (UTF-16, as `selectionStart`), `quote`. They are found once
  when the result arrives.
- On every `input` event the controller diffs the old and new value (common prefix and suffix give one edited
  range): suggestions after it shift by the length change; one that touches it is kept if the text at its
  new position still equals the quote, else searched for near the old position, else marked **stale**
  ("You changed this text after the grammar check…", only Dismiss is offered). This is the approach of
  `lint-framework`'s `spanMapping.ts`; copying that code with its Apache-2.0 notice is allowed.
- **Apply**: focus the field, `setSelectionRange(start, end)`, `document.execCommand("insertText", false,
  replacement)` so native undo works, then `htmx.trigger(textarea, "change")` so autosave runs (what
  `mdeditor_controller.js` does after a toolbar command). **Undo** on the card does the reverse if the text
  there still equals the replacement.
- **Clicking a card** scrolls the textarea to the passage and highlights it: a hidden mirror `div` with the
  textarea's font, width, padding and wrapping measures the range; the controller scrolls the textarea and
  draws one tinted box in a layer behind it (`.ed-body` already has a transparent background). A subject
  suggestion or title note highlights the subject input instead. The browser's own selection is not used for the
  highlight: the next keypress would replace the selected text.
- **Clicking in the text** (caret inside a suggestion's range) selects its card and scrolls the panel to it.
- **Dismissed grammar suggestions**: `localStorage` key `pcom:proofread:dismissed:<post id>` (or `:new` until
  the post has an id, then moved), a list of `{field, quote, replacement}`; matching suggestions from a later
  check are hidden. "N dismissed · show again" clears the list. Every access is wrapped in try/catch;
  without storage, dismissals last until the page is left.

**Style review state.** The panel shows the latest review: its summary ("Since review N" or "Overall"), then
its open notes, with a badge **New** or **Still open from review N** (from `continues`). A note whose passage
can't be found any more shows the quote it was about, dashed, with **Mark done** and **Keep as is**. **Done**
and **Keep as is** (which opens an optional "Why keep it?" field) are saved at once. "N done, M kept as is —
the next review knows about these." Below the list: "Note for the next review (optional)" and **Review
again**. **Earlier reviews** lists previous reviews (number, date, summary) read-only. **Start fresh**
deletes the post's reviews. A new post has no id until the first autosave; until then Style review is
disabled with the title "Available once the draft is saved". Deleting a post deletes its reviews.

**Limits.** Every call to Claude is a row in `proofread_requests`. The hourly limit counts the user's requests
of that kind with `status = 'ok'` in the last hour; a failed call doesn't count ("This attempt was not
counted"). Over the limit the service returns a `service.Invalid` whose message reads as a sentence, like
`posts.canPrompt`: "You have used all 10 grammar checks for this hour. The next one is available in 23
minutes." The panel shows "Grammar: 7 of 10 checks left this hour · Style: 2 of 3 reviews left this hour"
under the editor; every response carries both remaining counts. An optional site-wide daily cap
(`PROOFREAD_SITE_DAILY_REQUESTS`, 0 = none) answers "Grammar checks and style reviews are not available right now" when reached.

**Feature switch.** With `PROOFREAD_ANTHROPIC_KEY` empty, the feature is off: no buttons, no panel, and the
routes answer 404. Development and tests run with it off unless a key or WireMock is configured.

**Disclosure in the editor.** Wherever the buttons are shown, a line under the limits says: "Grammar
checks and style reviews are made by Claude, an external AI model from Anthropic. Your subject and text are
sent to it only when you press Check grammar or Style review." It is always visible, not behind a tooltip,
and the user guide repeats it.

**Privacy.** The privacy policy names Anthropic, says that subject and body are sent only when the author
presses one of the buttons, and that style reviews (text included) are stored with the post and deleted with
it. pcom stores no grammar-check text, only the request row (kind, model, token counts, time).

### Data

Migrations (one file per table is fine; `-- +migrate Up` / `Down` as in `migrations/`):

- `proofread_requests (id uuid pk, user_id uuid not null references users on delete cascade, kind text not
  null check (kind in ('grammar','style')), post_id uuid null references posts on delete set null, model text
  not null, input_tokens int not null default 0, output_tokens int not null default 0, status text not null
  check (status in ('ok','failed')), created_at timestamp not null)`, index on `(user_id, kind, created_at)`.
- `style_reviews (id uuid pk, post_id uuid not null references posts on delete cascade, number int not null,
  subject text not null, body text not null, summary text not null, author_note text not null default '',
  created_at timestamp not null, unique (post_id, number))`.
- `style_review_notes (id uuid pk, review_id uuid not null references style_reviews on delete cascade,
  position int not null, field text not null, kind text not null, quote text not null, before text not null,
  text text not null, continues_id uuid null references style_review_notes on delete set null, status text not
  null check (status in ('open','done','kept','carried')), keep_reason text not null default '',
  updated_at timestamp not null)`.

When a new review is stored, every open note of the previous review becomes `carried` if a new note
`continues` it and `done` otherwise (the author rewrote it away or the model no longer raises it); `done`
and `kept` notes stay as they are. Structs in `pkg/model` (`TestModels_MatchTheSchema` checks them).

env-namespace:"PROOFREAD"` (as `Media` is namespaced), each with a row in `config_test.go`'s table and in

| Setting | Env | Default |
|---|---|---|

| API base URL (WireMock in tests) | `PROOFREAD_ANTHROPIC_ENDPOINT` | `https://api.anthropic.com` |
| Grammar model | `PROOFREAD_GRAMMAR_MODEL` | `claude-haiku-5-5` |
| Grammar effort (`choice` low/medium/high) | `PROOFREAD_GRAMMAR_EFFORT` | `low` |
| Style model | `PROOFREAD_STYLE_MODEL` | `claude-sonnet-5-5` |
| Style effort | `PROOFREAD_STYLE_EFFORT` | `medium` |
| Grammar checks per user per hour | `PROOFREAD_GRAMMAR_PER_HOUR` | `10` |
| Style reviews per user per hour | `PROOFREAD_STYLE_PER_HOUR` | `3` |
| Site-wide requests per day, both kinds, 0 = no cap | `PROOFREAD_SITE_DAILY_REQUESTS` | `0` |
| Request timeout | `PROOFREAD_TIMEOUT` | `90s` |
| Most output tokens, grammar / style | `PROOFREAD_GRAMMAR_MAX_TOKENS` / `PROOFREAD_STYLE_MAX_TOKENS` | `8000` / `16000` |

configuration; tests use the constants. Input size is already bounded by `POST_BODY_MAX_LENGTH` and
`POST_SUBJECT_MAX_LENGTH`; the service rejects longer input with the same messages the post form uses.

### Packages

- **`pkg/proofread`** (new, pure): the request and result types, the JSON schemas, the embedded system
  prompts (`prompts/grammar.md`, `prompts/style.md`), the user-message builders, and the validation above
  (`Locate`, `Validate…`). The `Model` interface the service calls:
  `Grammar(ctx, GrammarInput) (GrammarOutput, Usage, error)` and `Style(ctx, StyleInput) (StyleOutput,
  Usage, error)`; `Usage` is model name and token counts. An in-memory fake for tests lives in
  `pkg/proofread/proofreadtest`.
- **`pkg/proofread/claude`** (new): the `Model` over the official Go SDK
  (`github.com/anthropics/anthropic-sdk-go`): `option.WithAPIKey`, `option.WithBaseURL` (the endpoint
  setting), the timeout, `MaxRetries` left at the SDK default. Structured output through
  `OutputConfig: anthropic.OutputConfigParam{Format: anthropic.JSONOutputFormatParam{...}, Effort: ...}`;
  check the SDK's current names against its README before writing (the claude-api skill's Go docs). Thinking
  is left unset (adaptive by default on these models). `stop_reason` `refusal` or `max_tokens` is an error,
  never a partial result. Services may not import `net/http` (`pkg/arch`), which is why the client is its
  own package, injected through `registry.Deps`.
- **`pkg/service/proofread`** (new): `CheckGrammar(ctx, actor, GrammarRequest) (*GrammarResult, error)`,
  `ReviewStyle(ctx, actor, StyleRequest) (*StyleReview, error)`, `StyleState(ctx, actor, postID)
  (*StyleState, error)`, `SetNoteStatus(ctx, actor, noteID, status, reason) error`, `ResetStyle(ctx, actor,
  postID) error`, `Remaining(ctx, actor) (Remaining, error)`. Options `WithLimits`, `WithModels` (names and
  efforts, passed to the `Model` per call), `WithLogger`; logging through `logging.FromContext`. Registered in
  `pkg/service/registry/registry.go` with a nil `Model` meaning off.
- **`pkg/repo/proofread.go`** (new): requests (insert, count since), reviews and notes (insert in one
  transaction with the status changes, latest review with notes, earlier reviews, set status, delete by post).

### Routes

All under `/controls` (login required); POSTs under `/controls/action` (CSRF). They answer JSON with a custom
handler like `upload_media` in `pkg/web/app/actions_media.go` (`jsonAction` only answers `{}`); errors go
through `reportError(c, actionMessage(err))` so messages match the other actions. New file
`pkg/web/app/actions_proofread.go`, mounted in `routes.go`.

Ids travel in the JSON body, not the path, like every other `/controls/action` route (`delete_draft`,
`create_share`, …): those routes are bound by `c.BindJSON`, and the route table lists them without
parameters. The one GET has no body, so its post id is in the path.

| Route | What it does | Body → answer |
|---|---|---|
| `POST /controls/action/proofread_grammar` | runs a grammar check on the text sent; counts against the grammar limit | `{post_id?, subject, body}` → `{suggestions: [...], remaining}` |
| `POST /controls/action/proofread_style` | runs a style review of the user's own post and stores it as the post's next review; counts against the style limit | `{post_id, subject, body, author_note}` → `{review, remaining}` |
| `GET /controls/proofread_style/:post_id` | loads the post's latest review with its notes and the list of earlier reviews, for the panel on page load; free | → `{review, earlier: [...], remaining}` (`review` is null if there is none) |
| `POST /controls/action/proofread_style_note` | marks a note done or kept as is (with an optional reason), or reopens it; free | `{note_id, status: done/kept/open, reason}` → `{}` |
| `POST /controls/action/proofread_style_reset` | **Start fresh**: deletes all reviews of the user's own post; free | `{post_id}` → `{}` |

`remaining` is `{grammar, style}`: the user's requests left this hour of each kind.

Each new route gets a row in `e2e/guards_test.go` (`TestGuards_RouteTableMatchesSource`).

### Stubbing the Anthropic API: WireMock

The browser and E2E tests run the app as a separate process, so the API is stubbed with WireMock (JSON stub
files, call verification), the choice F7 made for its translation backend. Task TM builds the helper once
for both waves; **whichever of F7 and F9 runs first does TM**, and the other drops it when it rebases.

- `pkg/testutil/wiremock`, shaped like `pkg/testutil/tommy`: one shared container per test binary, a pinned
  `wiremock/wiremock` 3.x tag, `testcontainers.Run`; imports registered mapping directories through the admin
  API; at cleanup, fails the test on unmatched requests and reports near misses; a verify helper over
  `github.com/wiremock/go-wiremock`. `e2e.WithWireMock()` starts it for the harness.
- Each API has its own path prefix. F9's stubs: `pkg/proofread/claude/testdata/wiremock/mappings/*.json`,
  prefix `/anthropic`, so `PROOFREAD_ANTHROPIC_ENDPOINT` is the container URL plus `/anthropic`. A stub
  matches `POST /anthropic/v1/messages` with an `x-api-key` header and a body `matchesJsonPath` on the model
  and a marker in the user message (tests use their own distinctive text), and answers a canned Messages API
  response whose text block is the structured JSON. A catch-all at the lowest priority answers 401 without
  the key.
