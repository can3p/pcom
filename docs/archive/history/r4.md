# R4 — Mailers (done 2026-10-07, branch `claude/zealous-shannon-ieo14d`)

**Built.** All 14 mails are declared in `pkg/mail`, one file per mail: a typed input with a `Header()`
method, samples built from in-memory models, and three embedded templates (subject and text through
`text/template`, HTML through `html/template`), parsed at init. `declare(...)` registers each mail, so adding
one touches no shared list, and `mail.All()` returns them sorted by name. `TestMails_Goldens` renders every
sample into `testdata/<sample>.golden`, and each constructor has a `_MatchesSample` test against its
sample. `Outgoing` was folded into `mail.Envelope`. The five admin notifications moved from `pkg/admin`
into `pkg/mail` as `Admin…`; `pkg/admin` keeps only `ClonedCustomRecovery`, whose report the router passes
to `AdminPageFailure` so `pkg/mail` doesn't import gin. The `/dev/mail` preview lists every sample and
renders its subject, text and sandboxed HTML. It is mounted only with `--dev-routes`/`DEV_ROUTES`, which
is off by default and on in `docker-compose.yml` and `.env.example`. `dbsender` now sends each due mail in
its own transaction (`ListDueEmailIDs`, then `LockDueEmail ... FOR UPDATE SKIP LOCKED` per mail), and
its retry schedule is `--email-retry-intervals` (default `10s,60s,30m`, the same four attempts as before).

**Decisions.**
- **Whitespace may change; content may not.** Every pre-existing golden differed only in whitespace when
  it moved to templates (`git diff -w` empty), including the admin goldens, compared by hand with the old
  text/html pairs. Two later changes were deliberate: samples use `SampleSite` with root
  `https://pcom.test`, so links became absolute, and the post-prompt-answer sample's post id became
  `post-2`, so it can't be confused with the prompt's post id.
- **The preview is behind a flag, not an admin route.** The owner chose a dev-only flag that production
  never sets over an admin page or a CLI that writes files.
- **No job queue in R4.** Mail already entered `outgoing_emails` in the same transaction as its change, so
  a queue would mostly help the feed poller. It became its own wave, R8, which took over open question Q9.
  R4 fixed only the sender's real defect: one transaction for the whole batch, so a failed update or
  commit resent every mail already sent.
- **Constructors kept their signatures**, so the services didn't change. The exceptions were the
  `Envelope` rename and the admin mails' move. The latter dropped an unused `site` parameter from two
  admin constructors.

**What went wrong.**
- S0 added two settings and broke `cmd/web`'s `serve --help` golden; M0 reported it. AGENTS.md now says a
  new setting rewrites that golden in the same diff.
- The worktree recipe linked the main checkout's `cmd/web/dist`, which didn't exist, and the dangling link
  broke E2E in every worktree. Each agent worked around it. E2E serves stub assets and needs no build; the
  `wave-run` skill now says so.
- The coordinator piped `make lint-q` through `tail` in an `&&` chain, so a lint failure (the shared lock)
  didn't stop the commit and cherry-pick. A later `make check-q` passed. AGENTS.md now forbids piping a
  quiet target.
- Three parallel tasks each wrote the same `sampleEnvelope` test helper; the clash at merge moved it into
  `golden_test.go`.
- The assertion audit found the comment mails' samples built through the constructors' own mapper, which
  made their `_MatchesSample` test circular. It also found an empty `SampleSite` that let a constructor
  ignore its site, the same id for a post and a prompt's post, a send-error test that exercised no mail
  code (it became a rollback test in the posts service), and redundant admin asserts. All were fixed, each
  proven by a mutation; the rule is now item 6 in `docs/testing.md`. Two pre-existing weak tests in
  `pkg/admin/panics_test.go` became #218.
- `UPDATE_GOLDEN=1` doesn't create a missing golden, so deleting the goldens to find orphans told nothing.
  `docs/testing.md` says so.
- In this sandbox, three browser tests fail as documented (older Chromium, no outbound network); CI's
  `browser` job decides them.

**Left out.** The job queue (R8). No `pkg/mail/AGENTS.md`: the package doc of `mail.go` holds the
conventions, and the AGENTS.md table points there. The branch is the session's designated branch rather
than `refactor/r4-mailers`, because the session could push nowhere else.

**Docs and skills changed.**
- `docs/architecture.md`: mail content (declaration, escaping, registry) and delivery (one transaction per
  mail, the retry setting).
- `docs/testing.md`: item 6 rewritten as the rule for mail goldens and constructor tests.
- `docs/running.md`: the `/dev/mail` preview and `DEV_ROUTES`.
- `docs/gogo-extraction.md`: the mail definitions now live in `pkg/mail/mail.go`; the queue entry points
  at R8.
- `AGENTS.md`: a table row for mails, the serve-help golden on new settings, never piping a quiet target.
- `wave-run` skill: worktrees need no `dist` for E2E; don't link the main checkout's.
- Plan: R8 added (and Q9 moved into it), R4's line dropped from the index, R7 no longer mentions R4.
