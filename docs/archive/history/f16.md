# F16 — Notes attached to a post (done 2026-11-22, branch `claude/modest-edison-sxt6oj`)

**Built.** An author gathers notes around a post without copying them into its text. A note is attached one by one
(from `/controls/notes`, the editor's Notes panel, or by inserting it), or a tag is attached and every note carrying
it, now or later, belongs to the post. A note a tag brings can be hidden from that post (`excluded`) without losing
its tag. The post page gives its author a Comments (n) | Notes (n) tab at `/posts/<id>#notes`, loaded from
`GET /posts/:id/notes` (404 for anyone else), grouped by how each note came and filtered by the tag bar.
`/controls/notes` hides notes that belong to a post unless All notes is on, shows each note's posts, and filters by
post from links with a removable chip. Attach to post… offers the last `NOTE_ATTACH_POSTS` (10) drafts and posts.

Schema: `note_post_link_how` gained `attached` and `excluded`, `note_post_links`' key became
`(note_id, post_id, how)` so a note can be inserted into and attached to the same post, and `post_note_tags` keeps
attached tags. The service methods are `Attach`, `Detach`, `Exclude`, `AttachTag`, `DetachTag`, `ForPost`,
`PostsOf` in `pkg/service/notes/attach.go`, owner only. A privacy test walks every reader of a post (another user,
a share link, anonymous, RSS, the zip export, the API, the feed, the subscriber mail) and checks none reaches a
note, with the author's own notes route as the positive control.

**Owner checkpoint, after T1.** The plan didn't have one; the coordinator added it as a task row before starting.
The owner then changed the design: inserting a note also attaches it; Append left the editor panel; Insert into post
left the post page; the "unused" filter became the default "hide what belongs to a post" with an All notes switch;
the post dropdown on `/controls/notes` gave way to links from the post; the attach picker became a capped recent
list. A second look found that the editor's This post | All notes switch didn't show which view was active, and
the owner moved the post page's tab from `localStorage` into the address. A new post in its scratch pad (F17) has no
post row, so Attach is disabled there until it is saved; the first build kept it disabled after the save until a
reload.

**What went wrong.**
- The default notes list hid attached notes, but the source chips still counted them; and NotePostLinkCount (the
  delete confirmation, the guard snapshots) counted every link kind once `attached` and `excluded` existed. Both
  were caught by the agents and fixed.
- A follow-up added an `hx-include` whose selector matched nothing on a new post; htmx logged a console error and
  five editor browser tests failed. The task had run only its own browser tests. Rule added to the preamble and
  `frontend-htmx`.
- The screenshot task created a post for its new shot, which then appeared in the journal and controls shots, and
  attached notes before the notes-list shot. Fixed by using the seeded post in the last row; rule added above the
  shot table.
- A new browser test raced a boosted navigation (`IsVisible` doesn't wait) and failed now and then; rule in
  `docs/testing.md`.
- One coordinator mutation check didn't apply (the `sed` pattern missed) and read as a pass; rule in `wave-run`.
- The owner saw a full page rendered inside the notes pane once. It was never reproduced; the `localStorage` tab
  memory was removed and the flow has a browser test.

**Left out, filed.** Note photos never loaded on master: the card linked `/user-media/<fname>` without a size class
(F15). Fixed on its own branch, can3p/pcom#303, with a capture-card thumbnail the owner asked for. A photo-only note
shows nothing in the editor's Notes panel and inserts a blank line: can3p/pcom#302. The demo seed has no attached
notes (the factory has no attach helper; the screenshot attaches through the app).

**Docs changed.** `docs/product.md` (Notes: attached notes and tags, privacy, the post page tab, the list's
default), `docs/guide/notes.md`, `docs/guide/writing.md`, `docs/running.md` (`NOTE_ATTACH_POSTS`), the new
`post-notes.png`. Rules: the checkpoint is a task-table row (`docs/implementation-plan.md`); `hx-include` targets,
view state in the address, and image size classes (`frontend-htmx`); waiting after a navigation
