# F10 — Styled HTML mails (done 2026-10-14, branch `feat/f10-mail-styling`, #237)

**Built.** Every HTML mail renders in two phases: the mail's own `<name>.html`, then
`templates/_layout.html` around it (the "pcom" wordmark linking to the site, a card in the site's light
colours, a footer saying why the reader gets the mail). `templates/mail.css` is inlined into `style`
attributes at render by go-premailer v1.37.0; the dark `@media (prefers-color-scheme: dark)` block stays in a
head `<style>`, marked `!important` by the inliner. `Header` gained `Site` (filled by every input; the six
mails that had no site take it as their constructor's first parameter) and `NoAccount` (set by the invitation
and waiting-list confirmation, which picks the "somebody entered this address" footer). The text parts end
with `templates/_footer.txt`. User mails (M1) have a heading, codes in `.mail-code`, bodies and prompts in
`.mail-quote`, the main link as a `.mail-button` with the raw URL under it; a new sample,
`new_post_rich_body`, shows markdown styled. Admin mails (M2) have a heading, details as a list, the failure
report in a sunken `pre`, no buttons. Tests: `TestMailCSS_MatchesTokens` (each annotated colour equals its
light or dark token in `_tokens.scss`; unannotated hex, `rgb()`/`hsl()` and named colours fail),
`TestMails_ClassesHaveRules` (doctype, footer link, text footer, dark block with token values, every class
has a light rule), `TestMails_FooterReason` (every sample, both wordings).

**Wrong or surprising.** `go:embed` skips files whose names start with `_`, so the directive is now
`all:templates`. `task_prompt.py` pasted only the M0 section, not the wave's "How it is built", which a
contract task implements; the coordinator pasted it by hand (now a rule in `wave-run`). M1 and M2 both
rewrite goldens in `pkg/mail`, and `UPDATE_GOLDEN=1` rewrites every golden in the package, so they ran in
worktrees (now a rule in `wave-run`). The assertion audit found six weak spots after M0's mutation check
passed: the colour check saw only hex, the class check also matched the never-inlined dark block, the dark
check matched only the `@media` string, the footer test covered four samples with no `NotContains`, the
narrowed escape assertion (the layout itself contains `"><`) duplicated the raw-tag check and was dropped,
and one admin test rendered with an empty site; all fixed in one round. A mutation that skips inlining is
caught only by the goldens. The cheap tier dropped "Hi!" from the admin mails despite "keep every sentence";
sent back once. Markdown headings render as `h3`, which `mail.css` didn't style; the coordinator added an
`h2`–`h4` rule. A fenced code block with a language gets a `language-*` class `mail.css` has no rule for:
harmless in sent mail (the element rules still apply), but the rich sample uses an unlabelled block so the
class check passes.

**Left out.** No preheader text, no unsubscribe or notification settings, no web fonts or images in the
layout. The text footer carries only `pcom · <site root>`, not the reason line. The owner's check in real
inboxes (Gmail, Apple Mail, Outlook) was not done before close; the PR is reviewable with `/dev/mail/<sample>`,
and findings become `mail.css` fixes.

**Docs changed.** `docs/architecture.md` (the mail line: layout, inlining), `docs/testing.md` item 6 (goldens
hold the full mail; the token test reads `_tokens.scss`), `docs/product.md` "Interface" (one layout, colours,
footer wording), the package doc of `pkg/mail/mail.go` ("Templates"), `wave-run` (paste the wave's shared
design into a task prompt; parallel golden rewrites in one package run in worktrees).

**Cost.** 1 coordinator session (67 turns, peak 157k context, 128k of tool results; flags: `cat`×3 in the
coordinator, `cat`×24 and raw builds×1 across the wave) and 7 subagents: M0 strong (resumed once for audit
fixes), M1 mid and M2 cheap in parallel worktrees (M2 resumed once), M3 cheap, and 2 strong read-only agents
(the M0 assertion audit and the docs fact-check). Skills: wave-run×1, wave-close×1. Cheaper than F8 (143
turns, peak 275k) for a wave of four small tasks; most coordinator turns went to verification and merging.
