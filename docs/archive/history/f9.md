# F9 — Grammar check and style review in the post editor (done 2026-10-14, branch `feat/f9-proofread`)

**Built.** Two buttons in the post editor, **Check grammar** and **Style review**, send the subject and
body to Claude through the server. `pkg/proofread` holds the types, the `Model` interface, the JSON
schemas, the embedded prompts and the validation of the model's answer (a quote must occur in its field,
located by `before+quote` or the quote alone, skipping matches already taken; quotes over code, link and
image destinations, raw HTML and block-tag lines are dropped, using the new
`pkg/markdown.ProtectedRanges`; the browser gets an occurrence index, never byte offsets).
`pkg/proofread/claude` is the client over the official Go SDK (structured output, the system prompt as a
cached block, refusal and `max_tokens` as errors). `pkg/service/proofread` and `pkg/repo/proofread.go`
check the actor and post ownership (through the posts service's `CheckEdit`), the per-user hourly limits
per kind over `ok` requests, an optional site-wide daily cap, and store each style review with its notes
and the previous notes' new status (carried or done) in one transaction. Five routes under `/controls`
answer JSON and 404 while `PROOFREAD_ANTHROPIC_KEY` is empty. The `proofread` Stimulus controller is a stub
that imports the panel as its own chunk: suggestions are applied with `execCommand("insertText")` so native
undo works, tracked through edits, marked stale when the text under them changes, dismissed per post in
`localStorage`; style notes are marked done or kept with a reason, **Review again**, **Earlier reviews** and
**Start fresh**; on phones the panel is a collapsible bottom sheet. The WireMock test container (task TM)
was cherry-picked from F7's open branch.

**Wrong or surprising.**
- F7 had already built TM, but its branch was 102 commits behind master with conflicts in a dozen files,
  so F9 branched from master and cherry-picked the one commit (conflicts only in `go.mod`/`go.sum`). The
  port still set F7's `TRANSLATION_*` variables in `e2e.WithWireMock`, which master doesn't have; caught
  while writing P4's prompt.
- The plan's occurrence count was always 0 by construction: the first match was always taken, so two
  identical mistakes without a distinguishing `before` lost the second. Matches already taken are now
  skipped, which makes the occurrence real.
- P1's block-tag regex required the line to end at `}`; the parser's regexes are anchored only at the
  start and accept tags inside quotes and lists. It now reuses the parser's regexes.
- P2's 401 stub was a catch-all for any request, so a request of the wrong shape got a 401 instead of
  failing as unmatched; and `contains` over the whole body matched the system prompt's own words.
- The plan left the author note and keep reasons unbounded: `PROOFREAD_NOTE_MAX_LENGTH` (2000) was added.
- P5's owned files missed the page plumbing (`write.html`, `edit_post.html`, `pkg/web/pages_posts.go`,
  `routes_posts.go`) that carries "feature on" to the first render; the agent edited them and said so.
- The panel pushed the first-visit bundle to 52.6 KB gzipped against a 50 KB budget; the owner chose
  lazy loading over a higher budget.
- P5's autosave assertion passed by timing: the keyup autosave from earlier typing fired after Apply and
  saved its result. After the fix, removing Apply's explicit `change` trigger still passes, because the
  textarea's native `change` on blur also saves; both paths are real.
- Deliberate typos ("teh") in browser tests failed `misspell`: P5 linted only its Go packages.
- The closing fact check found the cheap-tier docs task generalizing: the guide said the panel tells when
  the next check is available (the button is disabled; only a refused request says so), the privacy policy
  listed fewer request-row fields than the table stores and didn't say those rows outlive a deleted post.
- Every task's audit found weak tests after its mutation check had passed (whole-body stub matchers, an
  "open again" that started open, a reset test that never stored a review, a missing transaction test, no
  test for card highlight, caret selection or the phone sheet). Each was fixed in one round.

**Left out.** Underlining suggestions in the text (Harper's `lint-framework` is the candidate; the
suggestion data was shaped for it). Streaming style notes as they arrive. The model trial on the owner's
Russian texts and the final style-reviews-per-hour number (3 is a placeholder) wait for the owner and a
real key.

**Decisions.** Branch from master and cherry-pick TM rather than stack on F7 or rebuild it. `remaining`
also carries both hourly limits (for "7 of 10"). The site cap is a sliding 24 hours over `ok` calls, like
the hourly limits. A grammar check records `post_id` only for the actor's own post. "Still open from
review N" follows the `continues` chain to the review that first raised the note; note status changes
only on the latest review. Another user's style state answers 400 "Operation not allowed", as every action
does. The proofread service gets the registry's posts service instead of building its own.

**Docs and skills changed.** `docs/testing.md` (WireMock: match where the client puts the text, catch-all
stubs match only what they are for; the harness points at `/anthropic`), `docs/architecture.md` (third-party
API clients in their own package behind an interface, through `registry.Deps`), `frontend-htmx` (bundle
size and lazy-loaded controllers; autosave timing in browser tests), `docs/implementation-plan.md` (a page
that gets new data owns its whole path; every stored user text has a length setting; porting a task from
another wave's branch), `task_prompt.py` (lint `./e2e/...` when a task wrote tests there), coverage floors for `pkg/proofread`,
its client and its service, plus the
product rules, the guide's writing page with a screenshot, the privacy policy and `docs/running.md`.

**Cost.** 1 coordinator session (139 turns before closing, peak 268k context, 318k of tool results; flags:
`cat`×6, raw build×1) and 13 subagents: P0 and P3 strong (45 and 50 turns), P1, P2, P4 mid (16–24
turns), P5 mid (77 turns, peak 258k, 530k of tool results: the browser suite and its rebuilds), P6 cheap
(24 turns), 6 strong audits and fact checks (5–9 turns). Across the wave: `cat`×48, raw build×2, full
read×1. Skills: wave-run×1, wave-close×1, claude-api×1 (P0); P5 never loaded `frontend-htmx` although its
prompt named it, and its first lint missed the browser tests. Dearer than R6 (109 turns, peak 227k), as a
nine-task feature wave with a frontend should be; the audits paid for themselves, each finding something
the mutation checks had passed.
