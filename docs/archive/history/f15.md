# F15 — Notes: private snippets, typed or spoken, that feed posts (done 2026-11-07, branch `claude/awesome-knuth-mxojao`)

**Built.** Private notes for an author: typed, dictated (with a kept recording and a speech-to-text transcript),
photographed or shared in from the phone, then sorted on `/controls/notes` and used in posts from the editor.

- Schema: `notes`, `note_sources`, `note_tag_prefs`, `note_images`, `note_post_links`, `stt_requests`,
  `media_uploads.kind` (`note_audio`), the focus columns on `users`; API keys rebuilt as several per user,
  named, scoped (`full | notes`), with `last_used_at`, stored as a SHA-256 hash and shown once.
- `pkg/service/notes`: CRUD with single and bulk delete, `tags` + `text_tags` (`#word` in the body), hidden tags,
  rename and merge of tags and sources, stacks by `NOTE_SESSION_GAP` computed in the query, the focus with its
  idle expiry, Inbox, suggestions without a model, use records, the quote source rule, `Capture` (one path for
  the API, the capture page and the share target), audio upload, `Retranscribe`, the `notes.transcribe` job on
  its own River queue `stt` and the `notes.delete_audio` job.
- `pkg/stt` with an OpenAI-compatible backend (Groq by default), the shared retry layer and the per-user and
  site minute limits; WireMock mappings that also serve `docker compose` a canned transcript.
- `pkg/notes/capture`: shared text becomes a blockquote, a lone URL stays bare, typed text is stored as typed.
- Pages: the notes list (tag bar with include/exclude/off, hide, Inbox, suggestions, stacks, multi-select
  Tag/Source/Delete), the edit page, tag and source management, the Notes section on Controls, a header entry;
  `/controls/notes/new` with Dictate, Photo, Photo + dictate and Type, an IndexedDB queue and a service worker,
  in its own 14 KB bundle; the post editor's Notes panel (filter, search, Insert at the cursor, Append, Open,
  quotes with attribution); "Transcribe again as…"; transcripts replace a pending note in place.
- `POST` and `GET /api/v1/notes`, scoped keys on the settings page, the web app manifest at `/site.webmanifest`
  (it 404ed before, so the app could never be installed), the Android share target and app shortcuts.
- Settings: the `NOTE_*` group and the `STT_*` group (`STT_ATTEMPTS` among them); `DeleteFile` on media storage;
  named queues in `pkg/jobs`.

**Decisions.** Taken with the owner during planning (Q-N1–Q-N18) and during the run:
- Note photos stay public by URL like a draft's images (Q-N17, answered at the start of the run), so a photo
  goes into a post as it is; recordings are private and served only by an owner-checked route with `Range`.
- Kindle on iOS has no Share for a highlight, only Copy, and Live Text gives the bare passage too; the owner
  said to assume Android Kindle does the same. So there are no share formats to parse: the plan's Kindle
  parser became a three-way rule, and a quote takes the previous quote's source within `NOTE_FOCUS_IDLE`.
  The owner then decided shared text is stored as a blockquote the author edits afterwards; the parser's
  goldens are the owner's Russian Kindle and Dutch Live Text passages.
- A missing, malformed, unknown or revoked API key now gets `401` (it was `400`/`403`).
- The share target is the second CSRF-exempt route (after the token-carrying unsubscribe link).
- "Transcribe again" confirms whenever the note has text: the note keeps no copy of its last transcript.
- Weighed and rejected: self-hosted whisper.cpp (no CPU on the fly machine), the browser's Web Speech API (no
  result for an uploaded file, can't be redone), Deepgram and OpenAI (dearer than Groq for the same Whisper).

**What went wrong.**
- **The share target bypassed SameSite.** The first service worker queued every share it saw, so a cross-site
  form POST was accepted by the worker without a cookie and uploaded later with the victim's session. The T8
  security audit found it before merge to master; the worker now sends a share to the network first and
  queues only on a network failure, within the server's caps, and a browser test posts from a second origin.
- **A planned control was never built.** `Retranscribe` had a service method and tests but no route or button;
  every audit read tests, so only the docs task noticed. A follow-up task built it.
- **Weak tests in every task.** Each strong audit found tests that passed with the behavior broken: an offline
  test that passed online, a 413 that came from the generic body cap, a route matrix scraped from two files, a
  "not 401/403" check a 500 would pass. All were sent back before commit; the API matrix now comes from the
  router.
- **Bugs the audits and tests found in the wave's own code**: the edit page dropped the Notes button after a
  failed save; transcripts didn't appear until a reload; the selection bar kept ids of replaced items; the
  edit page's status poll broke after its first answer; field names `title`/`file` instead of `source`/`audio`
  ("larger than 0 MiB"); CRLF stored from multipart text; an aborted capture left photos in the bucket.
- **A flaky browser test** waited for the word "focus", which the page held before the click, and its next
  navigation raced the reload. Fixed with a wait for the reloaded row.
- **Coordination.** Two parallel tasks both wrote `partial--note-status.html` (one as a stub), which needed a
  hand merge; T7's worktree was removed before its audit fixes, so a fresh agent redid the context; two rate
  limits stopped four agents, all resumed with `SendMessage`.

**Left out.** By plan: notes in `blg`, a native app, server-side OCR, Kindle notebook import, attaching notes to
posts (F16), tags on posts, any AI on notes. Not done in the sandbox, for the owner by hand: building the iPhone
Shortcut, recording its raw requests into `e2e/testdata/shortcut/`, whether "Get Contents of URL" runs from
the lock screen, which mobile browsers start `?start=voice` without a tap, and the Android Kindle/Lens shares.
The provider prices in the plan's table could not be verified (the provider sites are blocked in the sandbox).
HEIC is refused until the image's libvips gets `vips-heif`. Bugs outside the wave, reported to the owner: a
cross-site POST to a `/controls` route logs the user out; the browser harness's `login()` sets cookies without
SameSite; the e2e harness pins tommy 0.3.0 while compose uses 0.3.1; `tools/dev-urls.sh` doesn't print WireMock.
`PUT /api/v1/image` without a file answered 500; fixed here (400) because the route matrix needs a real answer.

**Docs and skills changed.** `docs/product.md` (Notes section: privacy, tags, deleting, transcription, limits,
quotes, photos and HEIC, the STT provider, capture, the share target, scoped keys), `docs/running.md`,
`docs/api.md`, the guide (`notes.md`, `notes-on-a-phone.md`, `writing.md`, `settings.md`, `api.md`,
`overview.md`) with five new screenshots, the privacy policy; `frontend-htmx` (a page with its own bundle and
budget; the CSRF-exempt routes and why); `docs/testing.md` (wait for what only the action's result shows; a
route matrix comes from the router; `FailDeleteWith`); `docs/implementation-plan.md` "Planning a wave" (every
behavior names the task that builds its control; a service worker is a second server); `wave-run` (a worktree
goes only after its audit fixes are merged); `docs/plan/f16.md` no longer depends on F15.

**Cost.** 1 coordinator session (207 turns, peak 337k context, 147k of tool results; flags: `cat`×6 and one full
read in the coordinator, `cat`×178, full reads×4 and raw builds×6 across the wave) and 24 subagents: 11 tasks
(T0, T3, T5, T7, T8 strong; T1, T2, T4, T6, T9 mid; T10 cheap), 3 fix agents (T7 tests, T8 security, Transcribe
again), 9 strong read-only audits and 1 docs fact-check; 4 agents resumed after rate limits. Skills: wave-run×1,
wave-close×1, frontend-htmx in 8 subagents (median 101 turns against 11 for the rest, which says more about
the browser tasks being the big ones than about the skill), test-failure in 1. Heavier than F11 (186 turns, peak
299k, 416k of results) for a wave about twice its size; the coordinator's results volume fell by a third by
keeping long prompts in scratchpad files, and `cat` by subagents is again the largest waste.
