# R5 — bun and pgx instead of sqlboiler (done 2026-10-05, branch `refactor/r5-bun`)

**Built.** pcom queries Postgres through bun over pgx's `database/sql` driver. The models are hand-written
structs in `pkg/model`, one file per area, with sqlboiler's struct and field names. Nullable columns are
pointers, relations are plain fields named like sqlboiler's `R` fields (none had to be renamed), and enums
keep their names plus `All…`/`IsValid`/`String`. `TestModels_MatchTheSchema` replaces code generation: it
checks every struct against `information_schema` (columns, nullability, defaults, primary keys, a struct
per table). Repositories return the `pkg/model` types (Q13), `repo.Query(exec)` builds bun queries on the
Store's executor, and `repo.Executor` replaces `boil.ContextExecutor`. sqlboiler, `volatiletech/null`,
`pkg/model/core` (41k lines), `generate.sh`, the `generate`/`model` targets, CI's "Generated models are
current" job and the `model-shape` skill are gone.

The work ran in four passes:
- **S0, the driver swap.** pgx was swapped in under sqlboiler first, so a regression there would be the
  driver's. None showed up: timestamps, enums and jsonb behaved the same.
- **S1, the coordinator's contract work.** `pkg/model` was produced by a throwaway generator: reflection
  over the `core` types plus `information_schema`, because reading the generated code is denied. S1 also
  added the drift test, a reflection converter between `core` and `model` with a round-trip test, and
  seven spike tests pinning the bun behaviors pass C relied on.
- **B1–B4, the types swapped at the repository boundary.** Queries stayed on sqlboiler and converted
  through `convert.go`, with a scripted sweep over 121 caller files. These four tasks were committed as
  one commit.
- **C1–C6, the queries rewritten in bun,** in parallel worktrees. Then D deleted sqlboiler.

**What turned out wrong or surprising.**
- **Timestamps.** sqlboiler stamped `created_at`/`updated_at` itself on insert, update and upsert, and
  many of those columns have no database default. Each model now has a `BeforeAppendModel` hook doing
  the same. The plan hadn't listed it, which became the new "library swap" planning rule.
- **`nullzero` was the wrong tag** for defaulted columns: on update it writes NULL for a zero value (a
  `false` bool). Defaulted columns use bun's `default:` tag.
- **`bun.In` is deprecated** in bun 1.3; the code uses `bun.List`.
- **`FeedsToRefresh` bug.** Its `qm.Load(..., qm.Limit(1))` limits the whole query that loads subscriptions
  for every due feed, so at most one feed refreshes per poll. Filed as #213; R5 keeps the behavior and
  `TestBun_LimitOnAHasManyRelationIsShared` pins it.
- **Upserts differ case by case.** Each bun upsert reproduces sqlboiler's column set exactly. Feed and URL
  upserts return the existing row's id. `CountNewComment` only bumps `comments_number`; it never touched
  `updated_at`.
- **The arch test nearly weakened silently.** It counted a call carrying an executor as database work only
  because the type `boil.ContextExecutor` had sqlboiler's path in its name. After the rename it names
  `repo.Executor` explicitly.
- **`Page.mods` was a shared contract.** Three C tasks page their lists through it. It moved to
  `paging.go`, and its bun form `Page.apply` was written before dispatch.
- **Lint broke on helpers parallel tasks removed.** `toCoreEnums` lost its only caller in C1, so C1 deleted
  it; the other B-pass helpers were deleted after the merge.
- **Setup slips.** The C prompts named the wrong asset path (`cmd/web/client/dist` instead of
  `cmd/web/dist`), so a worktree's E2E run failed until the coordinator fixed the links. Parallel
  worktrees also clashed on golangci-lint's lock.
- **Committing mid-wave.** The stop hook wanted commits while B1–B4 were deliberately uncommitted. A
  snapshot went to `wip/r5-b` via `commit-tree` without moving HEAD. The proxy refused to delete that
  branch afterwards; it is the owner's to delete.

**Left out.** No behavior changed, #213 included. `.claude/settings.json` still denies reads of the
deleted `pkg/model/core`: it's a permission setting, so it's left to the owner. `tools/agent-stats.py`
keeps its `model-read` flag for past sessions. A `WithDriver` option in gogo's testcontainers would remove
`testdb`'s reopen with pgx; that is a gogo change.

**Decisions.**
- **bun over bob and sqlc** (owner): both generate code, bob is v0.x, and sqlc handles runtime filters
  and eager loading worst.
- **Q13 answered yes:** repositories return `pkg/model`.
- **Partial saves name their columns** through `model.UserColumns`/`model.LoginAttemptColumns`, checked
  by the drift test.
- **`repo.Executor` replaces `boil.ContextExecutor`.**

**Docs and skills changed.**
- `docs/architecture.md`: repositories return pcom's types; one driver and no codegen, with why bun; a
  new "Writing bun queries" section.
- `AGENTS.md`: the stack line, the area table and the reading rules.
- `docs/testing.md`: ground rule 1, `testdb` on pgx, sandbox notes, `CHROMIUM_PATH`.
- `docs/running.md`: no `make generate`; new columns go into `pkg/model`.
- `docs/implementation-plan.md`: the merge rule for models, and the new "library swap" planning rule.
- `wave-run` skill: worktree assets and the lint lock, removing finished worktrees, a helper whose last
  caller a parallel task removes, prompts in scratchpad files, backing up uncommitted work.
- `task_prompt.py` and the `wave-close` skill no longer name `model-shape`.
- Plan files: F7 (models in `pkg/model`), R6 (`volatiletech/null` and `friendsofgo/errors` are already
  gone), R7 (no longer runs alongside R5).

**Cost.**
- **Coordinator:** 1 session, 228 turns, peak 363k context, 249k of tool results; flags: `cat`×9, raw
  builds×8.
- **Subagents:** 9, with 289 turns and 668k of tool results between them. B1 strong; B3 and B4 mid; C1–C3
  strong and C4–C6 mid, in parallel worktrees. None was resumed for a failure. The two most expensive took
  173k and 131k of results.
- **Across the wave:** `cat`×34, raw builds×18, `model-read`×1.
- **Skills:** `wave-run` and `wave-close` once each in the coordinator; `frontend-htmx` once (B4).
- **Compared with F8** (143 turns, peak 275k): the coordinator ran longer and peaked higher, mostly on S1's
  contract work and on verifying nine tasks itself, while all but two subagents stayed under 115k peak.
