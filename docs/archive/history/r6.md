# R6 — Dependency hygiene (done 2026-10-12, branch `chore/r6-deps`, can3p/gogo#8)

**Built.** The last nine test files on `alecthomas/assert` moved to testify's
`require` (which, like alecthomas, stops at the first failure). `pkg/errors`
gave way to stdlib `errors` and `fmt.Errorf("...: %w")` in twelve files with
every message unchanged; the capitalized ones carry a `nolint` for
staticcheck's ST1005, which only stdlib constructors trigger.
`antonlindstrom/pgstore` was replaced by a new gogo package,
`sessions/pgstore` (gogo v0.3.0), which reads pgstore's rows and cookies so
nobody is logged out; its table is a sql-migrate migration that gogo's
`pgstore-migrations` command copies into `migrations/` under an install-time
timestamp, and a test fails when a gogo upgrade ships another. `web serve`
now deletes expired sessions (`--session-cleanup-interval`; pgstore's
cleanup never ran, so `http_sessions` only grew), and the 30-day session age
is `--session-max-age`. `lib/pq` left the server binary. depguard refuses
`alecthomas/assert`, `pkg/errors` and `antonlindstrom/pgstore`. `plan.txt`
became issues #221–#227 (two of its nine ideas had shipped), and `.devin/`
was already gone.

**Turned out wrong.** The plan was four bullets; checked against the tree it
had no tasks, `.devin/` didn't exist, and pgstore was worse than
"unmaintained" (runtime DDL, a second driver, no cleanup). A blind
`errors.Wrap` → `fmt.Errorf` conversion of `auth.go`'s `Wrap(session.Save(),
…)` would have failed every login, since `Wrap(nil)` is nil; the D2 prompt
named the trap, and a mutation showed only `pkg/forms`' login tests catch
it. D5 (sqlx → `database/sql`) was added mid-wave and dropped: gogo's
`transact` and `testcontainers/postgres` take `*sqlx.DB`, so the agent
started copying them into pcom (#229 waits for gogo). D1's lint failed on
D2's ST1005 findings in a shared package. The gogo store's first version
wrote MaxAge 0 rows as already expired, and its migration first shipped as a
`Schema` constant the sql-migrate command can't use, then under a fixed
dated ID; the owner's review moved it to an installer with install-time
timestamps. Docker failed to restart twice after container restarts (stale
containerd pid file).

**Left out.** `jmoiron/sqlx` (#229, after gogo drops it) and
goldmark-highlighting/chroma v2 (#228, may change highlighted HTML).
`pkg/errors` stays in `go.mod` as an indirect requirement of gogo.

**Decisions.** The session store went into gogo rather than pcom so every
gogo app shares it, reviewed there on its own; pcom's switch waited for R7
(gogo v0.2.0's `*zap.Logger`) and then joined this wave's PR instead of a
separate one. sqlx was dropped from the wave rather than duplicating gogo's
helpers in pcom. Expired rows read as missing, and a bad cookie gives a
fresh session rather than an error. `http_sessions` is exempt from
`TestModels_MatchTheSchema` like `migrations`: a library owns it.

**Docs and skills changed.** `docs/architecture.md` (sessions and the gogo
migration, the `pkg/pgsession` exemption), `docs/gogo-extraction.md` (the
store moved; gogo v0.3.0), `docs/testing.md` (testify only; the hook clears
the stale containerd pid), "Planning a wave" in `docs/implementation-plan.md`
(dropping a dependency starts at its other requirers), the `wave-run` skill
(check `task_prompt.py`'s guessed `PKG=` paths; lint findings in a shared
package belong to the task owning the file), and the SessionStart hook.

**Cost.** 1 coordinator session (109 turns recorded, peak 227k context, 117k
of tool results; flags: `cat`×10, raw build×2) and 6 subagents: D1 cheap,
D2 and D5 mid (D5's 31 turns thrown away), the `plan.txt` triage and the
gogo store strong; no audit agent, one mutation per task by the coordinator.
Wasteful calls across the wave: `cat`×17, raw build×5. Skills: wave-run×1,
wave-close×1. Dearer than R7 (109 turns, peak 214k) for a smaller diff:
the session spanned two repositories, three owner design rounds on the gogo
PR, two Docker restarts and a rebase over R7.
