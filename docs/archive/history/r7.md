# R7 — Structured logging with zap (done 2026-10-11, branch `refactor/r7-logging`)

**Built.** One `*zap.Logger` replaces the standard `log` package, `log/slog`
and the log-like `fmt` calls. `pkg/logging` carries it: `FromContext`,
`WithLogger` and `With` work on a plain context, a `*gin.Context` and its
`c.Request.Context()`, and return a no-op logger when none is set; `New`
builds it from `--log-level` and the new `--log-format` (`json` by default,
`console` in compose and `.env.example`); `Middleware` gives each request a
logger with a `request_id` and logs the request once served (error level on
5xx); `Recovery` logs a panic with its stack in both `ReportPanics` modes.
The router uses `gin.New()` with these instead of `gin.Default()` and adds
`user_id` once auth knows the user. gogo went to v0.2.0, whose
`forms.DefaultHandler` takes the request's logger. The mail sender, the feed
poller and the login pruner take a `WithLogger` option and put the logger
into the context they pass down; services, forms, auth, the media server and
the export action log through `logging.FromContext`; the markdown
transformers carry their own logger (variadic option, no-op default).
Subcommands other than `serve` log in the console format on stderr. depguard
forbids `log` and `log/slog` outside `pkg/logging`, tests included.
`pkg/testutil/testlog` records entries for tests.

**Turned out wrong.** L0's `WithLogger` on a gin context only stored the
logger in gin's own store; with `ContextWithFallback` off, about ten
handlers that call services with `c.Request.Context()` would have logged
nowhere. Found while reviewing L2, fixed in the coordinator's wiring commit
(the gin context now also replaces its request's context). The media server
was planned as a worker with `WithLogger`; it logs only inside requests, so
it takes the request's logger and no option. L1's first test covered the
poller-level failure but not the per-mail one (with `email_id`); the
mutation check caught it and L1 added the test. L3 was one call site and
was done by the coordinator. L4's prompt said "pkg/logging/zap", which
reads as a path; the coordinator rewrote the lint message.

**Left out.** No `X-Request-ID` response header and no request ID taken from
a proxy header. A page that panics with `REPORT_PANICS` on still answers 200
(it did before; filed as #230, not fixed here). `util.LocalizeTime` had no
callers and was deleted rather than converted.

**Decisions.** The logger is passed explicitly, never global. Workers take
an option, requests use the context. JSON is the default format, the one
the deployed app uses; development opts into `console` where it already
turns off production settings. A failed request is logged once by the
middleware; services log only what they swallow. `reader.CreateImageReplacer`
(owned by L1, called from L2's poller) got its new signature from the
coordinator before dispatch so the parallel tasks couldn't break each
other's build.

**Docs and skills changed.** `docs/architecture.md` gained "Logging";
`docs/testing.md` lists `testlog`; the README, `.env.example` and compose
set `LOG_FORMAT=console`; `docs/plan/f7.md` tells its worker task to take a
`WithLogger` option; the `wave-run` skill says a signature shared by two
parallel tasks is fixed by the coordinator before dispatch, and
`.claude/worktrees/` is now gitignored so running agents' worktrees don't
trip the stop hook.

**Cost.** 1 coordinator session (109 turns, peak 214k context, 122k of tool
results; flags: `cat`×11 across the wave, raw build×7, mostly `go test` on
one package while writing L0) and 3 subagents (L1 and L2 mid, in
worktrees; L4 cheap), no audit agent: the coordinator read the short test
diffs and ran one mutation per task. Skills: wave-run×1, wave-close×1.
Dearer than F2 (66 turns, peak 143k): L0 was written by the coordinator and
the session ran all five tasks plus the close.
