# F17 — A new post becomes a draft only when the author saves it (done 2026-11-21, branch `claude/pensive-sagan-kfegf0`)

**Built.** Before this wave the first autosave of a new post inserted a draft, so every post an author started
and abandoned stayed on the Controls page as "No subject". Now a new post's text lives in a **scratch pad** until
Save as Draft or Publish.

- Schema: `post_scratches` (one row per user and prompt, unique on `(user_id, coalesce(prompt_id, zero uuid))`
  so it works below Postgres 15; `revision`, `promoted_post_id`, `note_ids`) and `user_notices`
  (`(user_id, notice)`, `dismissed_at`).
- `pkg/repo/scratches.go`: load, insert-if-absent, update-where-revision-matches, empty-where-revision-matches and
  take-over, each one statement, so concurrent tabs are decided by the database.
- `pkg/service/posts`: a save without `PostID` goes to the pad unless it is `save_post` or `publish`;
  `SaveInput.ScratchRevision`, action `take_over`, `Saved.Scratch`, `*ScratchConflict{At, PromotedPostID}` as an
  error; promotion through the ordinary insert path (prompt link, notifications, mail); `Scratch` for `/write`.
- The Write page: "Not saved as a draft yet · kept <time>", Discard instead of Delete, `/write/preview` rendering
  the pad, the conflict notice with Load the newer text / Keep mine / Save mine as a draft and autosave paused in
  `postform_controller.js`, per-pad style-review dismissals, note ids inserted before the first draft kept in the pad.
- The one-time notice (`accounts` service, `dismiss_notice` action) and draft excerpts on Controls
  (`DRAFT_EXCERPT_LENGTH`, default 80, through `connections`).

**Decisions.**
- `Scratch` returns an emptied pad with its revision, not nil: with nil the form would send revision 0 and the
  first autosave after every promotion or discard would conflict (T0's finding; the plan said nil).
- Save as Draft and Publish from a stale tab create their post and leave the pad alone, so no text is lost;
  only autosave, the first autosave and Discard conflict.
- The owner's open questions on the notice (Q-S1 audience, Q-S2 retirement) were not answered during the run;
  the planned defaults shipped (every account, until dismissed) and both questions moved to
  `docs/open-questions.md`.
- Two tabs on one existing post still overwrite each other; filed as #291 when the wave was planned.

**What went wrong.**
- **T0 left the branch broken.** Making a new post's save return a pad made `pkg/forms` panic until T1 changed the
  form; T0 was committed alone, so one commit on the branch fails its tests. The planning rule on contract tasks
  now says a service task that changes its result owns the form that reads it, or lands with it.
- **A false frontend bug.** T1's subagent saw the production build compile the conflict check to `return false`
  and "fixed" it; the bundle in `cmd/web/dist` was a stale one left by the coordinator's own mutation check. The
  coordinator rebuilt, found the original line compiled fine and reverted the change. `docs/testing.md` now says
  to rebuild through `make test-ui` before reading a browser result as the frontend's doing.
- **Edits outside the task's list.** T1 needed `pkg/links` and F15's `notes/picker.js`; T2 needed
  `routes_posts.go` to pass the accounts service to `web.Write`. The planning rules already make a page task own
  its route; the plan missed it.
- **A missing config test row.** T2 added `DRAFT_EXCERPT_LENGTH` and its help golden but not its row in
  `TestServe_EveryVariable`; `make check-q` caught it. The "No magic numbers" rule in `AGENTS.md` now names it.
- **Audits found weak tests in every task**, as in F15: a badge check that could not fail, popup checks right
  after the click, a burst-typing test that wasn't deterministic (now holds a save in flight with a route), and
  untested rows (keep mine with no pad, discard after promotion, a conflict on a prompt's pad, the preview's
  404s). The T0 gap where `note_ids` was in the table but never stored was found by the coordinator.
- **Screenshots.** `controls.png` and `subscriptions.png` change on every `make screenshots` because they show
  relative times; restored by hand and filed as #296. The notice first spanned the page width outside
  `#form-container`; moved into the editor's column.
- A rate limit stopped T0; it was resumed with `SendMessage`. The coordinator's first dependency check saw F15 as
  open from a stale fetch and asked the owner, who said it had merged.

**Left out.** Two tabs on an existing post (#291). `wip/f17-t0`, the backup branch of uncommitted work, is left
for the owner to delete. `TestWriting_BlockquoteEditing` fails only in the sandbox and is now listed
in `docs/testing.md`. `TestNotes_PhotoFromTheToolbar` fails on master in CI too: since the image-caption change
an uploaded image has empty alt text, so lazysizes sees a 0×0 image and never loads it (#298, left for its own PR).

**Docs changed.** At T3: `docs/product.md` (the scratch pad, one writer at a time, the notice, preview, excerpts,
style review), `docs/guide/writing.md` (a "A new post" section) and its editor, grammar and notes-panel
screenshots, the `frontend-htmx` skill (how a test waits for a pad save). At close: a fact-check of T3's prose against the code
corrected two claims (which conflict choices are offered, the pad's note ids); `AGENTS.md` (config test
row), `docs/implementation-plan.md` (contract tasks), `docs/testing.md` (stale bundle), `docs/open-questions.md`
(Q-S1, Q-S2).

**Cost.** 1 coordinator session (97 turns, peak 191k context, 266k of tool results; `cat`×3) and 7 subagents:
4 tasks (T0 strong, 45 turns; T1 mid, 107 turns, peak 289k, 410k of results, the wave's largest; T2 mid, 44; T3
cheap, 28) and 3 strong read-only audits (6–12 turns each); 346 turns in all. Flags across the wave: `cat`×36
(16 in T1), raw builds×4 (all T1), full reads×3. Skills: wave-run×1, wave-close×1; no subagent loaded
`frontend-htmx` or `test-failure`, though T1 and T2 were template and browser-test work. Much lighter than F15
(207 coordinator turns, 24 subagents) for a wave of four tasks against eleven; `cat` by the mid-tier browser
task is again the largest waste.
